# REQ-016 A股全市场数据采集

## 背景与问题

当前研究工作区的“公司范围”选项是“当前公司”和“启用自选股”。用户提出数据获取应围绕维护清单或整个 A 股市场，不应受当前打开的公司限制。现有统一数据层只按启用自选股枚举目标，没有 A 股全市场标的入口。

2026-10-11 本地 GUI 走查确认，伊利页面的数据计划初始为当前公司，且只有“当前公司/启用自选股”两种范围。走查未发起联网采集。证据见[走查记录](../run-records/2026-10-11-REQ-016-GUI-UX-review.md)。

## 目标

- 在 GUI 中让用户独立于当前公司选择“已维护公司”或“全部A股”。
- 生成全 A 股计划时展示明确的股票范围、规模、请求量与可复用数据，再由用户确认是否联网。
- 将批量采集接入现有去重、进度、暂停/续跑、缺口解释与统一数据仓能力。
- 将同一轮 GUI 体验收口中的报告列表分层和变化报告可读性问题纳入子需求，一并交付与验收。
- 补足自选股的启停与信息编辑入口，并为全 A 股目录建立可追溯的快照存储与批次关联。

## 验收标准

- **AC-1**：数据获取页的“公司范围”选择器恰有两个选项：“已维护公司”和“全部A股”；当前打开的公司不改变这两个选项或其目标集合。数据档位、期次等其他计划参数仍可按现有界面选择。
- **AC-2**：选择“已维护公司”时，目标集合严格等于生成计划时自选股清单中已启用的公司；不自动加入当前公司、未启用公司或仅因 `output/` 中存在目录而识别到的公司。计划结果可列出目标公司并核对数量。
- **AC-3**：选择“全部A股”时，标的清单来自数据源提供的当前上市 A 股目录快照，覆盖沪、深、北交易所的 A 股普通股（含 ST），排除 B 股、基金/ETF 和已退市标的。计划与批次保存目录来源、获取时点及标的数量；无法确认某一交易所覆盖时明确列为缺口，不静默漏掉。
- **AC-4**：联网前的计划显示目录时点、目标公司数、数据档位、期次、数据组、目标总数、新增请求预估、可复用目标数，以及配额/权限未知项。预估无法确定的字段显示“未知”及原因，不用猜测值代替。此步骤不发起数据请求、不创建批次。
- **AC-5**：只有用户明确确认后才创建采集批次并联网；取消计划后零外部请求、零批次。批次执行中可查看当前公司/数据组、已完成与总目标、请求与复用计数；暂停后可恢复，已成功目标不得重复拉取。
- **AC-6**：批次完成或中断时，按公司与数据组列出成功、合法空响应、无权限、限频、错误及未完成数量，显示数据时点、剩余缺口及后续动作；不得将部分成功显示为全量完成。
- **AC-7**（实跑）：使用真实数据源在隔离沙箱中核对一次全 A 股目录快照和计划规模，并完成经预估后显式确认的全市场采集批次。报告记录可复制命令、数据源/环境、沙箱路径、退出码、计划标的数、实际请求/复用数、结果分布和发现的问题；token 只从 `.env`/环境读取，不写进日志或产物，真实 HOME 存档不作写入目标。

## 范围

**包含**

- 全 A 股标的目录获取、快照与行情/财报等既有数据组的全市场计划和批次。
- 数据获取 GUI 的两个范围选项及计划/进度/结果解释。
- 复用 REQ-011 原始数据仓的请求预估、去重、暂停续跑、缺口统计与离线重建边界。
- REQ-016.1 报告产物分类与普通用户列表展示。
- REQ-016.2 变化报告的自然语言表达与重大经营归因呈现。
- REQ-016.3 自选股启停与维护信息编辑。
- REQ-016.4 全 A 股目录快照与批次追踪。

**不包含**

- 港股、美股、基金/ETF、B 股和已退市公司。
- 自动、定时或启动即拉取；目录刷新不自动触发公司数据采集。
- 默认向真实 HOME 存档写入，或在没有用户确认的情况下联网采集。

## 约束与依赖

- 依赖 REQ-011 的标的清单、批次与统一数据仓，REQ-014 的自选股维护，以及 REQ-015 的 GUI 数据获取页。
- owner 已于 2026-10-11 批准将 `REQ-015.4 AC-4.1` 改为本需求的两个目标范围；该 AC 与父需求已回退至 `in-progress`，关联测试将在新范围实现时同步调整。
- 全市场规模可能带来大量调用。预检必须先显示请求量与未知项，联网前由用户确认；不得以“全部”作为跳过确认的理由。
- A 股目录以数据源实际支持的交易所范围为准并报告缺口；token 不入库、不进日志、不进提交。

## 子需求

### REQ-016.1 报告列表只展示面向用户的产物

- 状态：`in-progress`
- 目标：将用户可读报告与程序内部状态、输入和中间文件分层，普通报告列表只显示面向用户的报告。
- 验收标准：
  - **AC-1.1**：伊利报告列表及其他公司同类报告列表不显示 `latest.json`、`record.json`、`run_manifest.json`、`qualitative_input.json`、`data_pack_market_current.md`、章节解析文件等内部状态、输入或中间产物；受支持的用户报告和源材料仍可按产品设计浏览。
  - **AC-1.2**：被普通报告列表隐藏的内部文件不会因此从磁盘删除；列表分类有稳定、可回归验证的规则，未知类型不会误标为用户报告。
- 追溯：源问题为 REQ-009 M3；走查证据见 `docs/run-records/2026-10-11-REQ-016-GUI-UX-review.md`；测试与 PR 待实现时登记。

### REQ-016.2 变化报告先讲清经营变化与关键归因

- 状态：`in-progress`
- 目标：让缺少财会知识的读者无需自行翻查报表或先掌握会计术语，也能理解主要经营变化、重大财务事项、关键证据及归因边界。重大事项的跨材料识别与定性依据由 [REQ-017](REQ-017-financial-report-events.md) 完成，本子需求负责把结论以读者优先的方式呈现。
- 验收标准：
-  - **AC-2.1**：执行摘要先用日常中文回答“经营和利润发生了什么变化、影响有多大、主要解释是什么”；收入与归母净利润等关键指标说明变动方向、幅度、比较期间和口径。`run`、`bundle`、`D7`、`selected_chars`、`max_evidence`、`prior_analysis` 等流水线术语不得作为面向读者的主线。
-  - **AC-2.2**：遇到重大会计事项时，摘要/差异清单优先说明事项是什么、为什么重要、涉及哪个期间与报表项目、金额及对利润/资产/现金流/期间可比性的影响；涉及商誉减值、会计差错更正、审计意见或监管处理时使用通俗解释，关键解释不得只藏在附录或原始报表中。
-  - **AC-2.3**：伊利 2026H1 报告须显著说明澳优商誉减值和存货减值是本期资产减值增加的重要原因，列出报表金额及来源，并说明商誉减值是对收购形成、预计无法收回部分确认的费用；税前减值不能直接等同于归母净利润下降额，税费、少数股东影响或因果贡献未核实时必须明示。
-  - **AC-2.4**：五粮液相关材料须分别说明 2026 年对 2025 年一至三季度部分报表项目的前期会计差错更正，以及证监会历史行政处罚所认定的信息披露违法事实。会计更正不能单独推导为财务造假；除非权威决定明确对相应主体和报告期作出造假/虚假记载认定，否则报告不得用“造假”给更正事件定性，并须准确说明文件日期、涉及期间、来源与认定状态。
-  - **AC-2.5**：对上述重大解释逐项标注原始定期报告、公告或监管文件的可定位证据，并将已披露/监管确认事实、公司解释、分析推断和未核实事项明确区分；无法取得来源或关键口径时写明缺口，不以模型补写事实。
-  - **AC-2.6**：数据缺口、证据限制和后续动作保留，但不遮蔽关键经营变化；普通读者可从报告正文追溯到对应证据。
- 追溯：源问题为 REQ-004 M1；走查证据见 `docs/run-records/2026-10-11-REQ-016-GUI-UX-review.md`；测试与 PR 待实现时登记。

### REQ-016.3 在界面维护自选股启用状态与公司信息

- 状态：`in-progress`
- 目标：在已有添加、导入、移除能力上，让用户能管理哪些公司参与“已维护公司”采集范围，并修正清单信息。
- 验收标准：
  - **AC-3.1**：数据页可对清单中的公司启用或停用，并编辑显示名及数据档位；无需离开 GUI 或输入命令。停用公司仍留在清单中，但不会进入“已维护公司”的采集目标集合。
  - **AC-3.2**：启停或编辑后，清单、采集计划和公司页面在刷新后显示同一状态及信息；新增与现有用户可见文案符合 REQ-012 的文案约束。
  - **AC-3.3**：启停、编辑与移除均只修改清单配置，不删除原始数据、分析记录或报告产物；界面明确区分“停用”和“移除”。
- 追溯：既有添加/导入/移除能力见 REQ-014；测试与 PR 待实现时登记。

### REQ-016.4 全 A 股目录快照与批次追踪

- 状态：`in-progress`
- 目标：将全 A 股目录作为可审计的独立快照保存，并让每个计划和批次固定引用使用的目录版本。
- 验收标准：
  - **AC-4.1**：目录快照结构化保存数据源、获取时间、快照标识/内容摘要及逐标的代码、名称、交易所和上市状态；快照记录与用户自选股清单分开维护，不能将“启用跟踪”状态混作上市状态。
  - **AC-4.2**：每个“全部A股”计划及批次引用一个确定快照标识，并可查目标数量、沪深北覆盖与排除项；恢复或审计批次时仍能还原当时的目标集合，不因后续目录刷新而变化。
  - **AC-4.3**：目录更新生成新快照并保留旧快照；代码新增、退市、交易所/名称变化可按快照比较，数据缺失或交易所覆盖不确定时明确报告，不静默覆盖历史。
- 追溯：依赖 REQ-011 SQLite 原始数据仓；当前实现设计需在实现 PR 中登记并验证快照表/记录与迁移方案；测试与 PR 待实现时登记。
