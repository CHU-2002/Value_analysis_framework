# REQ-015 公司研究工作区

## 背景与问题

owner 于 2026-10-10 要求以产品经理与 QA 身份试用项目，并提出一个新 REQ，指出图表、
agent/模型选择、报告查看和远程数据过程难用。提案依据正式 main `88dc97f` 的真实浏览器
走查及一次真实数据源调用，完整步骤、观察与截图见
[GUI 体验走查](../run-records/2026-10-10-GUI-UX-review.md)。

| 用户想完成的事 | 当前观察 | 影响 |
|---|---|---|
| 找到研究入口 | 左侧“工作台/数据/公司/任务/分析”分组标题集中排在所有链接之前，标题与所属页面脱离；公司研究页与全局工具平铺 | 分不清层级，把不可点击的分组文字误认为导航 |
| 判断一家公司的趋势 | 股价实际是年度最高/最低/年末收盘折线，未提供蜡烛 K 线；无日/月/季/年切换、历史 PE/百分位时间序列、范围/缩放/数值表；营收与利润共轴 | 无法按熟悉的行情操作核对价格与估值在同一时点的变化 |
| 决定谁来生成报告 | 全局已选伊利仍要手填代码；无 agent/模型控件，配置依赖进程环境与 CLI 默认 | 无法在生成前选择成本/能力，无法辨识将使用什么模型 |
| 找到正确报告并读完 | 先呈现整篇定性报告，再列 72 个产物；两个价值报告均标作“定性报告”，无列表日期/最新标识；选到的旧报告正文日期是 2026-06-09 | 查找入口埋在正文底部，版本容易误选；缺目录/查找/比较 |
| 判断数据能否支持分析 | 空仓显示“没有缺口”；导入后完备度 22/23 与补缺口计划 37 个目标并列，分母范围不解释；批次以 ID、done/partial/frugal 为主 | 不知道拉到了什么、还缺什么、哪些分析受影响、下一步做什么 |

走查还复现了 **REQ-013.3 的预检回归**：全局选中公司后，即使填写合法代码，仍被
“报告动作只接受股票代码”阻断；清除全局公司后相同代码通过。
该问题登记在 REQ-013 的维护任务 **T13**，不作为新能力重新编号；旧 AC 不修改。

**新编号的理由**：本条新增公司研究导航、真实 K 线与估值联动时间轴、GUI 内的 agent/模型选择、按版本组织的阅读器与
面向分析用途的采集结果解释，形成完整的公司研究路径。REQ-012 明确不包含图表缩放，
REQ-013 明确不包含 GUI 模型选择，既有报告浏览也未承诺目录/全文查找/版本比较。
已有预检、分类和空仓文案缺陷仍在原需求维护，本条不替代 REQ-009/012/013。

## 目标

1. 按“全局入口 → 公司研究页签 → 页面操作”组织界面；选定公司后连续完成数据、生成、阅读与图表核对。
2. 在 GUI 中选择实际执行的 agent 与模型，并看清预检结果、运行状态与本次产物。
3. 把数据过程转成可理解的业务信息：范围、进展、取得的数据、缺口、分析影响和下一步。
4. 用标准 K 线与统一的日/月/季/年时间轴核对行情和估值；以用户任务验收，保留审计、安全与测试门禁。

## 产品方案（提案）

### 导航与页面职责

| 层级 | 用户看见的入口 | 职责与交互 |
|---|---|---|
| 左侧全局导航 | 工作台、公司、任务 | 都是可点击页面；工作台看待办，公司入口搜索/选择公司并维护自选股，任务看正在运行/历史任务 |
| 公司研究页顶部 | 公司名称/代码及切换器；概览、行情与估值、报告、数据 | 四个页签都是可点击导航，有选中态；公司切换始终可见，公司上下文贯穿页签 |
| 页面操作 | 更新数据、生成报告、导出、阅读某版本 | 按钮放在对应内容页；生成报告配置在公司研究路径内打开，避免变成另一个顶级目录 |
| 高级入口 | 数据页内的批次/原始存档；报告页内的迭代记录；高级工具内的命令目录 | 保留已有能力；操作入口和研究内容分层，技术细节按需展开 |

“公司”入口保留全部本地公司的检索，不因未加入自选股而隐藏既有产物；清单维护继续依赖
REQ-014。全局侧栏不重复列出所有公司页签。若保留分组标题，标题紧邻其所属链接，
折叠组须是可操作按钮；纯标题有明确的次要视觉，不能伪装成选中页签。

### 行情与估值：一套时间操作，多张联动图

```text
公司：伊利股份 600887.SH                       [更新数据] [生成报告]
[概览] [行情与估值·当前] [报告] [数据]

周期 [日] [周] [月] [季] [年]    范围 [近1年] [近3年] [近5年] [全部] [自定义]
复权 [不复权/前复权/后复权]       指标 [PE(TTM)] [PE历史百分位] [PB] [PB历史百分位]
┌ K线主图：蜡烛 / MA5、10、20、60 / 十字光标 / 开高低收 ┐
├ 成交量副图：与每根K线对应                            ┤
├ PE(TTM)副图：同一时间坐标，独立倍数轴                 ┤
└ PE历史百分位副图：同一时间坐标，0—100%轴              ┘
分位统计窗口 [近3年/近5年·默认/近10年/全部历史截至该日]
覆盖：实际起止日期 / 最新交易日 / 缺口 / 数据来源      [数值表] [导出]
```

首屏优先展示 K 线、成交量、PE 与 PE 历史百分位；PB/其百分位按需开启，更多指标遵守
同一时间操作契约。窄桌面可局部纵向滚动，工具栏不压住图形。财务趋势另放同页的财务区，
保留“年度/半年/单季”**财务口径**，不把财报期次当成交易时间周期。

| 控件 | 改变什么 | 必须保持的关系 |
|---|---|---|
| 日/周/月/季/年 | 一根 K 线或一个指标点代表多长的自然交易期间 | 所有行情/估值图同步；改变数据聚合，不只是改刻度文字 |
| 近1/3/5年、全部、自定义 | 看哪段历史 | 图形同步缩放/平移；不改变分位统计窗口 |
| 分位统计窗口 | 每个历史时点与此前多少年的有效日数据比较 | 改窗口重新计算分位；改显示周期只抽取对应期末点，不重新用月/年样本算排名 |
| 财务年度/半年/单季 | 财报数字的期间和累计/单期语义 | 与交易周期独立，不在日轴上造出每日财报数值 |

参考[同花顺官方行情页](https://stockpage.10jqka.com.cn/HQ.html)的日/周/月 K 与
前复权/后复权/不复权入口；季/年周期来自 owner 本次要求。此处“同花顺格式”具体指下面
AC 的蜡烛、量价分区、均线、读数和时间操作，不宣称逐像素复制或官方合作。

## 验收标准

- **AC-1**：同一研究路径的图表、数据、生成、阅读共享公司上下文；选一次即可进入各步，
  不再手填同一个代码或路径。切换 A→B 后各页只显示 B 的数据；已经提交的 A 任务与产物链接
  保留 A，不被当前选择重绑。刷新、前进/后退和分享本机链接后公司/报告版本一致；
  无公司、无数据、无报告分别提供相应下一步入口。
- **AC-2**：图表满足 `.1`：标准蜡烛 K 线与成交量、PE/PB 历史值及百分位共享
  日/周/月/季/年周期、范围与联动光标，能缩放/平移/重置和核对精确值；
  交易周期、复权、财务口径与分位窗口分别解释，数值表/导出一致，缺失不伪装成零。
- **AC-3**：报告生成满足 `.2`：能选择 agent/模型，展示预检与配置来源，
  选择传到执行并可审计；不修改 CLI 全局配置，不静默换模型，不自动重跑。
- **AC-4**：报告阅读满足 `.3`：正文前可选类型/版本，能辨识正式发布与历史，
  目录定位、文内查找、版本比较与任务产物直达均可用。
- **AC-5**：数据体验满足 `.4`：执行前范围明确，执行中进展可读，结束后能解释取得的数据、
  未完成目标、分析影响和恢复方式；记录数、计划完备度与请求数分别标注。
- **AC-6**：在 **1440×900 与 1024×768** 桌面视口完成以上路径，主页面无整页横向溢出；
  长表/代码在自身区域滚动，阅读正文可换行。公司/指标/范围/模型/报告选择、目录与确认
  可仅用键盘完成，焦点可见。常用信息不要求先展开技术日志，实际 argv/退出码/原始日志
  仍可展开；凭据不进入界面、日志或产物。
- **AC-7**（实跑）：独立 QA 用真实浏览器、真实本地产物和沙箱存档跑完整研究路径，
  覆盖至少两家公司、有/无数据、有/无报告、历史版本与部分成功；至少一批真实采集、
  一次真实 agent 报告生成。记录命令、环境、截图、观察、退出码、实际 agent/模型和
  本次产物归属；修复缺陷须提供能抓住该缺陷的失败→通过对照。真实账号不足以运行第二种
  agent 时明确记录未测，该 agent 不冒充已获实跑验证；第二种协议仍须假 CLI 合同验证。
- **AC-8**：导航满足 `.5`：全局入口、公司页签、操作按钮层级明确；可见导航可点击，
  选中态/键盘/前进后退一致，不能出现集中排在链接前面的孤立分组标题；既有能力仍可到达。

## 子需求

### REQ-015.1 标准 K 线与估值联动时间轴

- 状态：`in-progress`
- 目标：用熟悉的行情操作对齐价格、历史估值与百分位，定位并核对变化。
- 验收标准：
  - **AC-1.1**：股价主图是真实 OHLC 蜡烛 K 线，有上下影线、开/高/低/收读数、默认红涨绿跌
    （收盘相对开盘）、十字光标；平盘可辨识且不只靠颜色。下方成交量逐根对应、单位明确；
    提供可切换 MA5/10/20/60，均线周期按当前 K 线根数计，历史不足不造值。
    财务年度最高/最低/年末收盘汇总不能代替 OHLC；缺开盘等字段时明确不能生成 K 线。
  - **AC-1.2**：提供 **日/周/月/季/年**，以及近1/3/5年、全部、自定义范围；默认日线、近1年。
    每种周期按该市场交易日归入自然周/月/季/年，开盘取首笔、高取最高、低取最低、收盘取末笔、
    成交量求和；标注区间首末交易日，未结束期间标注“进行中”。休市不补零，停牌与缺数分别说明。
    支持放大/缩小、平移和一键重置，日轴可看精确交易日期，年轴不挤成每日标签。
    使用跨年/季度、休市、停牌与至少10年历史样本验证每档实际聚合与范围边界。
  - **AC-1.3**：PE(TTM)、PE 历史百分位、PB 与 PB 历史百分位提供同一组周期/范围控件；
    K 线、量、估值副图同步缩放/平移/十字光标，按日期对齐，Y轴各自标倍数/量/百分比。
    月/季/年等估值点取该期间末交易日的真实指标；该日缺失则留缺并标注，不能向前悄取另一日。
    日期、OHLC、成交量、PE/PB、百分位和数据来源均可从光标及可键盘操作的数值表核对。
    隐藏指标、切换公司、无数据范围时有正常反馈，不残留旧公司曲线。
  - **AC-1.4**：历史分位使用同一指标的有效日样本，统计窗口可选近3/5/10年及全部截至该日，
    默认近5年。对每个交易日 t，窗口只包含截至 t 的有效观测，分位为
    `100 × 窗口内严格小于当日值的样本数 / 窗口内有效样本数`（包含当日，等值不算更小）。
    PE/PB 非正数、缺失值不参加分位排名；当日不可排名则显示原因，不画成0%。
    明示实际历史范围、样本数与不足完整窗口的状态；显示范围、K线周期与复权切换不改变
    同一日/同一统计窗口的百分位，绝不引入未来交易日样本或把分位均值当期末分位。
    用带相等值、非正值、缺值的序列逐点核对，并断言追加未来观测不改变此前点。
    数据源事后修订须有来源/版本说明，不宣称还原了当时已知财务信息。
  - **AC-1.5**：提供不复权/前复权/后复权并明确当前选择，价格、OHLC 与均线采用相同有效
    复权依据；成交量不随价格复权改变，PE/PB 使用其真实数据源口径而非复权价除最新盈利。
    缺少复权依据则禁用对应选项并说明；除权日样本可核对。不得用最新年报/当前股本回填
    整段每日 PE。现有年末估算 PE 与新增真实日 PE 明确区分来源、频率，不悄改旧估值结果。
  - **AC-1.6**：财务区仍提供年度/半年/单季、日期/期次范围与指标显隐；对至少10年及半年/
    单季样本，图形、图例、数值表同步。季度累计不得冒充单季，缺少换算依据说明不可用。
    营收与利润差至少10倍时默认分图或明确独立轴。两种规定视口无标题/单位/图例/刻度重叠
    或截断，信息行至少8 CSS px间距；缺数断线、有原因，不补零。
  - **AC-1.7**：图片与 CSV/TSV 导出反映当前公司、显示周期/范围、指标、财务口径、复权、
    分位窗口及数据时点；数值表保留可核对精度。浏览/切周期/导出均离线，不自动联网补历史。
    数据不足时显示真实覆盖起止与缺口，提供带公司/指标/所需日期范围的“更新数据”入口；
    由数据页展示计划/权限/请求预估并显式确认，取回后离线建图。不把缺历史伪装成完整十年。
- 追溯：实现 PR / 测试 TBD；需新增 OHLC/历史估值序列契约与必要复权数据，不仅修改绘图外观。

### REQ-015.2 可选择 agent 与模型的报告生成

- 状态：`in-progress`
- 目标：生成前看清并选择执行配置，生成后能追溯实际使用的配置与产物。
- 验收标准：
  - **AC-2.1**：生成页默认带当前公司，动作是已有三个白名单；提供 agent 与模型选择。
    首批接入既有 **Codex、Claude Code** 两种协议，本机未安装者显示禁用原因/安装登录指引。
    模型选项随 agent 切换更新，来自该 agent 提供的目录或本地维护的配置目录，显示来源；
    不把配置目录中的模型宣称为账号已授权，不要求用户填 CLI 路径或凭据。
  - **AC-2.2**：可选择“沿用 CLI 默认”或具体模型；默认模型无法解析时明确写“默认模型未知”，
    不猜模型名。安装/登录/模型兼容性分别显示“已确认/未验证/不可用”及依据；
    已知不兼容则禁用，无法离线确认则显示未验证，最终确认中保留该提醒。
    预检不触发分析调用、不产生报告/任务。非法 agent/模型组合在服务端拒绝，零外部分析进程。
  - **AC-2.3**：确认界面显示公司、动作、agent、具体模型或默认来源、联网/额度影响和预计
    产物；技术详情可看完整 argv。确认前切换配置会重新预检；取消无任务、无调用。
    指定模型仅作用于本次进程，任务记录保存请求配置与 CLI 回报的实际配置（未知则写未知）；
    两种假 CLI 均断言所选模型确实收到，真实实跑核对 CLI 回报。失败不静默换模型或自动重试。
  - **AC-2.4**：提交后直接显示本任务进展，可跳到任务中心，离开后返回能找到；生成结果直达
    本次报告与变化报告。CLI 退出 0 但缺少声明产物时明确标示“报告未产出”，不标生成成功；
    同公司不同 agent/动作仍遵守既有互斥，切换公司不改变已提交任务与产物归属。
- 追溯：实现 PR / 测试 TBD；扩展 `agent_action.py` 与 agent 插件；先修 REQ-013 T13。

### REQ-015.3 报告阅读与版本比较

- 状态：`in-progress`
- 目标：无需理解文件名/目录即可找到、阅读、比较正确的报告。
- 验收标准：
  - **AC-3.1**：正文之前提供报告类型与版本选择，区分商业质量/价值分析/变化报告/源材料；
    每版显示期次、生成时间、任务或 run 来源、有效/过期/不可用状态；缺少元信息写未知。
    默认入口优先按所选类型的正式发布指针/迭代台账定位，无法解析时显示说明与可选历史，
    不以文件名顺序或 mtime 猜正式最新版。两份同类文件无须读正文或路径即可辨识版本。
  - **AC-3.2**：长 Markdown 报告有由真实标题生成的目录、锚点跳转、文内查找/结果计数/
    上下项定位、返回顶部及专注阅读模式。标题重复也能准确跳转；查找无匹配时给正常状态。
    表格局部滚动、长证据 ID/代码不撑破正文，技术 JSON 默认折叠但保留可查看/下载。
  - **AC-3.3**：可选同公司、同类型两个历史版本比较正文变化，显示两版的期次/时间/
    数据时点，并能跳到已有变化报告；明确区分正文差异与业务结论，不自动新增投资判断。
    只有一版时说明无可比版本；切公司不保留跨公司的比较对象。
  - **AC-3.4**：报告与源材料分层浏览，PDF/JSON 等非 Markdown 提供可用打开/下载入口，
    不送入 Markdown 渲染器产生失败卡；从任务结果点开直接选中本次版本，刷新后仍一致。
    导出/下载对应当前选中版本，沿用路径 jail 与安全渲染边界。
- 追溯：实现 PR / 测试 TBD；消费 REQ-010 发布指针、REQ-003 迭代台账与任务产物链接。

### REQ-015.4 采集过程与结果解释

- 状态：`in-progress`
- 目标：用户能判断数据是否足够、采集花了多少调用、下一步如何完成分析。
- 验收标准：
  - **AC-4.1**：执行前可见本次公司范围（当前公司/自选股）、期次、数据档位及覆盖哪些
    中文业务数据组（财报/行情/股东治理/利率等）、新增请求预估和将复用的记录。
    所选范围进入服务端计划，确认取消不联网；接口名和参数仅放技术详情。
  - **AC-4.2**：执行中显示排队/正在采集/等待限频/暂停/完成，当前公司与数据组，
    已完成目标/总目标、实际请求与缓存复用分别计数；未知耗时不造 ETA。
    离开再返回、服务重启后已落盘批次仍可查看；部分成功/用户暂停有恢复或补缺口入口，
    无权限/限频/无数据分别解释，不用同一句“失败请重试”概括。
  - **AC-4.3**：完成页汇总新增/复用/无数据/失败/未完成，并按公司/业务组展示数据时点、
    剩余缺口及对图表/报告的影响；可跳至受影响页或显式发起离线重建。
    实际成功 2/2 的批次显示成功，不把整仓另一期次的无权限误算成该批失败；
    批次部分成功也不冒充全部可用，采集结束不自动宣称报告已更新。
  - **AC-4.4**：分析用途的完备度按当前公司/期次/档位的**同一目标计划**计算；分母包含
    尚未尝试的目标，并注明分母范围。已有记录统计单列，不与计划完备度混称。
    空仓显示“尚未采集”，不能显示“数据齐全/无缺口”；完整、合法空响应、无权限、
    限频、未尝试和过期分别解释及给下一步。只补缺口预估与剩余目标可相互核对，
    请求次数可能受缓存/重试影响时说明差异，提供计划明细以审计。
- 追溯：实现 PR / 测试 TBD；消费既有数据层计划、批次、目标结果与业务数据集描述。
