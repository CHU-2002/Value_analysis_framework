# REQ-009 本地图形化控制台（可扩展框架 + 按键执行 + 股票图表 + 报告与迭代记录浏览）

## 背景与问题

框架现在**只有命令行**：`scripts/` 下 20 多个脚本、14 个用户可见入口、run-store 的 6 个子命令，
全部要靠记参数手敲。实际使用中的痛点（来自当前仓库状态，不是主观判断）：

- **入口分散**：README 的「怎么用」列了 slash command、「直接跑 Python 脚本」又列了 11 条命令，
  另有 `scripts/results/` 的 4 步管线；没有一处能一眼看全「这个项目能干什么」。
- **看图要自己动手**：`data_pack_market.md` 里已经算好了 §11 十年周线行情（11 年年度高低/年末收盘/周均量）、
  §12 关键财务指标（9 个期次的 ROE/毛利率/净利率/资产负债率…）、§3~§5 三大报表，
  但都是 Markdown 表格，**没有图形**，趋势要靠逐格读数字。
- **产出散落**：`output/600887_伊利/` 下有 31 个文件（报告、数据包、PDF、synthesis、contexts）。
  报告是 Markdown，要另外转 HTML 才能好好读；`scripts/report_to_html.py` 目前覆盖率 0%、也没人点得到。
- **迭代记录看不懂**：REQ-003 的 run-store 已经落盘 `history.jsonl`（追加式迭代台账）、
  `latest.json`（当前生效指针）、`runs/{run_id}/run.json`、`record.json`，但**只能 `cat`**；
  「这次增量更新相对上一次改了什么结论」（`conclusions_changed`）散在 JSON 里，看不出时间线。
- **必然会被不断加需求**：使用者已明确表示会持续给 GUI 提新需求（新页面、新图表、新数据源、
  新的可视化类型）。若第一版把页面与接口**硬编码**在服务里，之后每加一个需求都要改核心文件，
  改动互相耦合、无法独立评审与回滚。

也就是说：**数据、图表源、报告、迭代记录都已经落盘了，缺的既是一个能点、能看的面板，
也是一个「加功能不用动核心」的框架。**

## 目标

- 先立起**可扩展框架**：内核只做传输与调度，任何 GUI 功能都是**插件**；
  将来加页面/面板/图表类型/数据源/按键，**只加插件，不改核心**。
- 让**远程数据只在你说的时候才拉**：把心一横租来的高权限账号用「采集批次」**一次性拉全**，
  原始数据长期存档在本地，之后几个月都不必再拉；**拉过的绝不重复拉，缺什么一眼看得见**。
- 再让「这个项目能做什么」变成一屏可见、可点的按键，不必记参数。
- 让已落盘的行情与财务数据变成图，趋势一眼看得出；**图表数据本地缓存**，
  浏览路径不联网、不重复解析、更不会每次都去远程拉取。
- 让产出报告和 run-store 迭代台账能在同一个面板里读完，不用来回 `cat` 与转 HTML。

## 验收标准

- **AC-1**：一条命令启动本地面板：`make gui`（等价 `.venv/bin/python -m scripts.webui`）启动后打印可点击的本地 URL；
  服务**只监听环回地址**（默认 `127.0.0.1:8765`，端口可配），显式要求绑定非环回地址时被拒绝并给出可读理由；
  默认端口被占用时以非 0 退出码报错，不静默改端口。
- **AC-2**：所有既有用户可见入口以按键形式提供，且**复用既有实现**（面板不另写一套业务逻辑）。
  被覆盖的入口清单（以 README「怎么用」与「直接跑 Python 脚本」为准）：
  `tushare_collector.py`、`discover_report.py`、`download_report.py`、`pdf_preprocessor.py`、
  `value_analysis_engine.py`、`buy_sell_plan.py`、`buy_sell_engine.py`、`valuation_engine.py`、
  `portfolio_engine.py`、`screener_core.py`、`report_to_html.py`、`md_to_mobile_html.py`、
  `analysis_status.py`、`runs.py` 的 `new`/`resolve`/`finish`/`adopt`/`export`/`downstream`、
  `scripts.results` 管线的 `prepare`/`reconcile_results`/`synthesis`/`resolve_qualitative`。
  点击按键后显示：实际执行的命令行、运行中状态、退出码与 stdout/stderr 尾部。
- **AC-3**：提供必要的股票图表——基于**本地已落盘产物**至少绘制 3 类图：
  (a) 年度股价走势（最高/最低/年末收盘，来自 `data_pack_market.md` §11「十年周线行情」）；
  (b) 关键财务指标多期趋势（ROE/毛利率/净利率/资产负债率，来自 §12）；
  (c) 营收与归母净利润按期次对比（来自 §3 合并利润表）。
  图表数据全部来自本地文件，**不联网**；鼠标悬停能读到具体数值。
- **AC-4**：报告与产出可读——能按公司列出报告与产物（定性分析报告、变化报告、`value_computed.md`、
  买卖计划、数据包、PDF 等），点击后在面板内渲染阅读（标题/列表/表格正常显示），
  并能在公司、期次与 run 之间切换。
- **AC-5**：迭代记录可读——面板展示 run-store 迭代台账：按时间**倒序**列出 `history.jsonl` 的每次 run
  （run_id、kind、创建时间、supersedes、期次、框架指纹、结论变化），标出 `latest.json` 指向的当前生效 run，
  并对变化型 run（`report-update`）展示它相对被取代 run 的结论变化（`conclusions_changed`）；
  `history.jsonl` 缺失的公司显示空时间线而不是错误页。
- **AC-6**：安全边界——面板**不提供任意命令或任意路径输入**：命令走白名单 + 结构化参数表单且**不经过 shell**；
  文件访问限制在 `output/` 之下，拒绝 `..`、绝对路径与越界符号链接；页面上不回显 `.env` 内容或 token。
- **AC-7**：无新增第三方依赖且全 mock 可测——实现只用 Python 标准库与仓库既有依赖
  （不改 `requirements.txt` / `requirements-test.txt`）；测试不联网、不依赖真实 `output/`、不 import 新包；
  新增测试规模在 `docs/TEST_SCOPE.md` 的 scope 预算内
  （4 个测试文件：`tests/test_webui_framework.py`、`tests/test_webui_archive.py`、
  `tests/test_webui_server.py`、`tests/test_webui_views.py`，合计 ≤ 64 条用例），确需上调时按 `docs/TESTING.md` §5 写明理由并经需求 owner 批准，
  不得为让门禁变绿而放宽判定。
- **AC-8**（实跑）：在真实机器上实跑——`make gui` 启动后用浏览器打开面板，对 `output/600887_伊利`
  依次点开报告、3 类图表与 2 个 run 的迭代时间线，并点一个按键跑一条真实命令（含退出码与日志回显）；
  报告里记录命令、环境（Python/浏览器/端口）与观察到的界面现象。
- **AC-9**（可扩展性不变量）：**新增一个 GUI 功能不得修改框架核心**——加页面、面板、图表类型、
  数据源、按键、任务类型时，只新增/修改插件模块与前端渲染器注册，
  不修改 `scripts/webui/core/*`、`static/index.html` 与 `app.js` 的分发逻辑；
  由「演示插件」测试（在临时目录通过 `--plugins` 加载，其导航/面板/接口/数据集自动生效）
  与核心文件指纹断言共同判定。

### REQ-009.1 按键执行器与任务生命周期

- 状态：`accepted`
- 目标：既有入口全部变成可点的按键，点下去就能跑、能看到进展与结果。
- 验收标准：
  - **AC-1.1**：`POST /api/v1/jobs` 提交任务后**立即**返回任务 id（HTTP 不阻塞到命令结束）；
    `GET /api/v1/jobs/{id}` 返回 running/finished/failed、退出码、stdout/stderr 尾部与起止时间。
  - **AC-1.2**：`GET /api/v1/commands` 返回按键清单，覆盖 AC-2 列出的全部入口（测试逐项断言），
    每条含结构化参数定义（名称、是否必填、默认值、取值约束），参数定义与各脚本真实 CLI **双向**一致
    （表里的 flag 必须存在于脚本；脚本里 `required=True` 的 flag 必须在表里）。
  - **AC-1.3**：未知命令、未在参数表声明的参数、白名单外的命令、取值含 `;` `|` `&&` `$(` 或换行一律 4xx 拒绝，
    且**不启动任何子进程**；命令不以 `shell=True` 执行；并发任务数有上限，超限返回 429。
  - **AC-1.4**：任务历史落盘（任务 id、命令、参数、退出码、起止时间、日志尾部），
    面板重启后仍能查看已完成任务；落盘日志与响应里的 token 一律脱敏。
- 追溯：`tests/test_webui_server.py`；PR #TBD

### REQ-009.2 报告浏览、图表与迭代台账视图

- 状态：`accepted`
- 目标：不跑命令也能看懂已有产出——读报告、看图表、看迭代记录。
- 验收标准：
  - **AC-2.1**：`GET /api/v1/companies` 返回 `output/` 下全部公司目录及其最近一次 run 与 `primary_period`；
    `output/` 不存在时返回空列表而不是 500。
  - **AC-2.2**：`GET /api/v1/companies/{dir}/artifacts` 按类型分组返回产物（相对路径、大小、修改时间）；
    `..`、绝对路径、指向 `output/` 之外的符号链接一律 4xx 拒绝。
  - **AC-2.3**：Markdown 报告在面板内渲染为 HTML，且报告里的原始 HTML/脚本被**转义**（`<script>` 不生效），
    用一条注入用例断言。
  - **AC-2.4**：`GET /api/v1/companies/{dir}/charts` 从本地 `data_pack_market.md` 解析出至少 3 组序列
    （年度行情、关键财务指标、营收/归母净利），返回前端可直接绘制的 `{labels, series:[{name, values}]}`；
    文件缺失或表格格式变化时返回带原因的错误响应而不是未捕获异常；

  - **AC-2.5**：`GET /api/v1/companies/{dir}/runs` 按时间倒序返回 `history.jsonl` 的 run 列表并标出

### REQ-009.3 可扩展框架与本地数据层

- 状态：`verified`
- 状态说明：PR #44 合入 → 门② 第一轮验收**不通过**（`AC-3.3` 不成立 + 阻断项 D1/D3）→ 回退 `in-progress`
  → PR #45 修复 D1~D10 → 第二轮复验发现 N1（响应体泄漏 token，`AC-3.7` 不成立）→ 修复 N1~N9
  → 第三轮复验 **`AC-3.1`~`AC-3.7` 全部成立、无阻断项**，推进 `verified`。
  三轮验收报告与复验记录见 [`docs/verification/2026-09-21-REQ-009.3.md`](../verification/2026-09-21-REQ-009.3.md)。
- 已知取舍：P3（降级提示里带内部绝对路径）不修，本机自用可接受；若将来面板对他人可见（另开 REQ）必须收窄。
- 目标：立起一个「加功能不用动核心」的微内核框架，并把图表等派生数据的**本地缓存与失效**
  做成框架能力，让所有后续 GUI 需求都只写插件。
- 验收标准：
  - **AC-3.1**：内核与启动——`python -m scripts.webui --port 0` 启动后 `GET /api/v1/healthz`
    返回 200 且带框架版本与 API 版本；服务只绑定 `127.0.0.1`（请求绑定非环回地址被拒绝并给出可读理由，
    且**不提供任何配置项把服务暴露到非环回地址**）；默认端口被占用时非 0 退出、不静默改端口。
  - **AC-3.2**：插件注册表与扩展点——框架提供六类注册点（导航/页面、面板、API 路由、数据集、按键、任务类型），
    插件通过 `contribute(registry)` 声明式注册；**新增一个 GUI 功能只新增插件文件并在
    `plugins/__init__.py` 登记一行（或用 `--plugins <目录>` 加载仓库外插件），不改核心**；
    并由「演示插件」测试判定：在临时目录注册的导航/面板/路由/数据集**自动生效**，
    同时断言核心文件（`core/*`、`static/index.html`、`app.js` 分发逻辑）的内容指纹未被改动。
  - **AC-3.3**：声明式面板协议——服务端返回的页面与面板描述是**纯数据**（JSON，带 `schema_version`），
    前端按 `kind` 选择渲染器，渲染器本身可注册；**未知 `kind` 必须降级为可读提示卡片而不是白屏或报错页**；
    至少 3 种 `kind`（表格 / 图表 / 时间线）有渲染契约测试（给定面板描述 → 断言 DOM 结构或渲染输出的契约字段）。
  - **AC-3.4**：本地数据层与缓存——所有派生数据（图表序列、产物索引、迭代台账）统一经数据层获取，
    数据集声明「源文件 + 解析器 + 解析器版本」；缓存条目带指纹
    （`sha256(解析器版本 + 参数 + 源文件内容摘要)`）并原子写入（`.tmp` → `os.replace`）；
    **同一输入第二次读取不重复解析**（解析器调用计数断言）；源文件内容变化或解析器版本升级后缓存**自动失效**并重算；
    缓存目录可配置、可清理，且位于 `output/` 之下（不污染仓库，也不与既有产物混放）。
  - **AC-3.5**：零远程依赖的浏览路径——面板启动、页面浏览、图表与报告读取**不发起任何远程请求**；
    远程数据（Tushare / yfinance）只能由用户显式点击按键触发既有脚本产生，落盘后由数据层索引；
    由一条**禁用网络**（socket 被 stub 为抛错）下浏览类接口仍全部正常返回的测试断言。
  - **AC-3.6**：API 契约与稳定错误码——所有接口在 `/api/v1` 前缀下，统一信封
    `{ok, schema_version, data, warnings, meta, error{code, message, hint}}`；
    错误码是**稳定枚举**（不允许把异常文本当错误码）；失败路径（坏 JSON、未知路由、越界路径、
    源文件缺失、表格格式变化）各返回对应错误码且不抛 500 堆栈；由契约测试锁住。
  - **AC-3.7**：安全中间件——统一的路径 jail（`resolve()` 后必须仍在 `output/` 子树内，符号链接按真实路径判定）、
    静态资源 jail、请求日志与任务日志的 token 脱敏（用 `TUSHARE_TOKEN` 的实际值做替换）；
    由失败路径测试断言（穿越、绝对路径、越界符号链接、token 不出现在响应与日志里）。
- 追溯：`tests/test_webui_framework.py`；PR #44（框架切片）；验收报告
  [`docs/verification/2026-09-21-REQ-009.3.md`](../verification/2026-09-21-REQ-009.3.md)（**不通过**）

### 独立验收缺口登记（REQ-009.3，2026-09-21）

| 编号 | 程度 | 现象（可复现场景） | 去处 |

| **D1** | **阻断** | 客户端渲染面板的 `endpoint` 取数分支**不可达**：服务端恒写 `data` 键（无 provider 时为 `null`），前端只在 `data === undefined` 时 fetch → 图表永远取不到数据 | **本切片修复**（修取数契约 + 契约测试）；`REQ-009.2` 的开工前置 |

### REQ-009.4 手动触发的远程采集与长期存档

- 状态：`accepted`
- 目标：让「租一次高权限账号、一口气拉全、之后长期不拉」成为一等公民——拉全、存住、不重复拉、
  缺什么一眼看得见。
- 背景（使用者的真实用法）：目前是**只能拉很少数据的 Tushare 年包**；将来会**短时间租用高积分账号**，
  一次把所需数据全部拉下来，然后长时间不再发起第二次拉取。因此设计目标不是「点点就联网」，
  而是**批次化 + 存档化 + 缺口可识别**：把有限的高权限窗口用在补齐缺口上，而不是重复劳动。
- 验收标准：
  - **AC-4.1**：**手动触发边界**——采集只能由显式动作触发（面板按键或 CLI 子命令）；
    框架不提供定时器、不启动即采集、不页面加载即采集；未配置 token 时触发返回明确错误码
    （`NO_TOKEN`）并给出可读指引，且**零次远程请求**；测试断言不存在自动采集代码路径。
  - **AC-4.2**：**采集批次与配额档案**——一次采集 = 一个批次，声明目标清单（代码/期次/数据板块集合）、
    配额档案（`frugal` 低配额年包 / `bulk` 租用高配额）与存档根；批次有唯一 id、状态
    （running / paused / done / partial / failed）与进度（已完成 / 总数）；
    触发前给出**调用量预估**（目标数 × 各档位板块数）并要求确认（`--yes` 可跳过）。
    `frugal` 只拉低配额下的必需板块，`bulk` 拉全量板块与全期次。
  - **AC-4.3**：**原始数据长期存档**——远程返回的原始数据按「数据集 / 标的 / 期次」落盘到**可配置的存档根**
    （默认 `~/turtle_archive`，**不在仓库内**），每条存档带元信息：接口名与参数、抓取时间、
    token 指纹（sha256 前 8 位）、配额档案、框架版本、响应内容摘要（sha256）、字节数；
    存档**不随 TTL 过期**，与既有 `output/.collector_cache/` 的 7 天 TTL 缓存**明确分层**（前者是资产，后者是临时缓存）；
    框架不主动删除存档，删除需要显式动作 + 二次确认。
  - **AC-4.4**：**去重与断点续跑**——同一（接口 + 参数 + 期次）已有存档时**默认跳过**并计入「命中存档」，
    只有显式 `--force` 才重拉；批次进度每完成一个目标即落盘，中断（Ctrl-C / 崩溃 / 取消）后重启同一批次
    **只补未完成目标，已完成的不重拉**；同一批次运行期间不允许重复启动（返回 `BATCH_RUNNING`）；
    批次结束时报告「新增请求数 / 命中存档数 / 失败数 / 跳过（无权限）数」，供核对配额消耗。
  - **AC-4.5**：**权限与积分缺口可识别**——把「无权限 / 积分不足 / 频率超限」与「该数据真为空」**区分开**，
    每个目标记录结果枚举 `ok` / `empty` / `no_permission` / `rate_limited` / `error` 与错误原文摘要；
    批次产出**机器可读的缺口清单**（缺什么、为什么缺、属于哪个接口与期次）与完备度统计
    （如 `12/14` 板块）。
    > 现状问题（本 AC 要修掉的盲区）：`scripts/tushare_modules/financials.py:1083` 等处把权限错误与
    > 空数据统一写成「数据缺失 (接口可能无权限)」，`data_pack_market.md` 末尾也只有一行
    > 「共 N/M 个数据板块成功获取」——使用者无法据此判断「租高权限账号能补到哪些数据」。
    > **2026-09-25 实跑补充证据**（REQ-006.1 的 AC-1.9 复跑，run `20260925T042255414048Z`）：
    > `yc_cb` 连续 5 次返回「抱歉，您没有接口(yc_cb)访问权限」，但数据包底部**仍写
    > 「共 14/14 个数据板块成功获取」** —— 完备度把「无权限」当成了成功，比原描述更严重
    > （不只是措辞含糊，而是统计口径错误）；§14 无风险利率另写「数据缺失 (接口可能无权限)」。
    > 这也实测确认了「**无限次调用 ≠ 全接口权限**」（该 token 调用次数不设限，但仍无 `yc_cb` 权限）。
  - **AC-4.6**：**按缺口补齐与完备度**——在高配额账号下可按缺口清单**只补缺口目标**（不重拉已完备部分）；
    补齐后缺口清单相应收敛，完备度更新；面板显示每个公司/期次的完备度与缺口原因。
  - **AC-4.7**：**token 安全与批次留痕**——token 只从环境变量 / `.env` 读取；面板不接收、不存储、
    不回显 token；存档与日志只记录 token 指纹（sha256 前 8 位）与用户填写的档位标签
    （如「年包 2000 分」/「租用 5000 分」），用于将来判断「这批数据是哪个权限拉的、可能缺什么」。
  - **AC-4.8**（实跑）：用**真实 token** 实跑并留档——① 低配额账号下拉一个批次，记录哪些板块返回
    `no_permission` 与错误原文；② 中途中断后重启同一批次，确认已完成目标未被重拉；
    ③ 条件允许时用高配额账号按缺口清单补齐，记录补齐前后的完备度与调用量统计。
    报告里给出可复制的命令、token 档位标签（**不写 token 本身**）、观察结果与本次发现的问题去处。
- 追溯：`tests/test_webui_archive.py`；PR #TBD

## 约束与依赖

- **零新增依赖**：只用 Python 标准库与仓库既有依赖；CI 只装 `requirements-test.txt`，
  新增第三方包会同时拖慢 CI 并可能顶破 scope 预算（实测 2026-09-21：测试文件 33/40、用例 1522/1600，
  本需求三个测试文件合计 ≤ 52 条用例，仍在预算内）。
- **核心不含业务**：`scripts/webui/core/*` 不得出现任何具体功能（不得硬编码 `/api/companies` 这类路由）；
  功能一律落在 `plugins/`。这是 AC-9 的实现约束，也是「加功能不改核心」的前提。
- **面板是入口不是副本**：按键必须调用既有脚本/模块；业务逻辑不得在面板里重写。
  命令清单若与 README 漂移，以 README 为准（AC-1.2 双向校验）。
- **本地优先、离线优先**：视图路径只读 `output/`；远程只在用户显式点按键时发生（AC-3.5）。
  **缓存失效 ≠ 重新采集**：前者只丢派生数据并重算，后者才联网，UI 上必须是两个不同的动作。
- **存档根默认在仓库之外**：原始存档是「花钱租账号换来的」资产，默认放 `~/turtle_archive`（可配），
  不放 `output/`（gitignore 目录容易被顺手清理）；框架只读它、不删它，删除必须显式且二次确认（AC-4.3）。
- **复用既有取数实现**：采集批次的协议、限流、重试复用既有 `scripts/tushare_modules/` 与
  `tushare_collector.py` 的客户端（`_safe_call` / `rate_limit` / `MAX_RETRIES`）；
  **既有 `data_pack_market.md` 的产出与退出码保持不变**——采集只在外层做编排、存档与缺口统计。
- **存档不含凭据**：token 只从环境变量 / `.env` 读取；存档与日志只记 token 指纹（sha256 前 8 位）
  与用户填写的档位标签（AC-4.7）。
- **全 mock、不联网**：测试不依赖真实 `output/`，产物一律写 `tmp_path`；新增测试文件归 `unit` 层

- **不改既有契约**：run-store 的 `run.json` / `history.jsonl` / `latest.json` / `record.json` 与

  同日再按使用者要求**新增采集与存档切片 `REQ-009.4` 并置于交付顺序第 2**
  （原话：「框架中加入额外子需求：手动触发远程数据拉取与存储。目前我充值了只能拉取很少数据的 tushare
  账户包年，后续会考虑租用短时间的 tushare 账户，一口气把所有信息拉取，然后长时间内不再进行第二次拉取」）。
- **技术栈决策**：使用者在三选一中选定「只用 Python 标准库 `http.server` + 手写单页前端，零新增依赖」，
  理由是 CI 只装 `requirements-test.txt` 且 scope 预算只剩 78 条用例，引入 Flask/前端框架或
  Streamlit 都会同时顶破依赖与测试门禁。设计与取舍见 `docs/GUI_CONSOLE_PLAN.md`。
- **框架决策（本轮，详见设计文档）**：
  - **微内核 + 插件**：内核只做传输/路由/信封/安全/调度，功能全在 `plugins/`；六类注册点（导航、面板、
    路由、数据集、按键、任务类型）。可扩展性由 AC-9 的「演示插件 + 核心文件指纹」判定，不是口号。
  - **声明式面板协议**：服务端返回纯数据的页面/面板描述，前端按 `kind` 渲染，渲染器可注册，未知 `kind` 降级。
  - **三层数据模型**：源层（`output/` 既有产物，只读）→ 派生缓存层（`output/.webui_cache/`，带指纹，
    原子写）→ 请求内存层（同请求内共享一次解析）。
  - **「避免每次都从远程拉取」的三条保证**：① 浏览路径永不联网（AC-3.5）；② 远程只有显式按键才发生，
    由既有脚本落盘到 `output/`；③ 落盘结果被数据层索引并缓存，后续浏览命中缓存。
    另外把「**缓存失效**（丢派生数据、离线重算）」与「**重新采集**（联网跑脚本）」做成两个不同动作，
    并在面板上显示数据生成时间与缓存徽标，让用户自己决定何时值得联网。
- **采集与存档决策（`REQ-009.4`，详见设计文档 §9.1）**：使用者的真实用法是「低配额年包日常用 +
  短租高积分账号一次性拉全，然后长期不拉」，因此采集被设计成**批次 + 存档 + 缺口清单**三件套，
  而不是「点点就联网」：
  - **手动边界**：没有调度器、不启动即拉、不页面加载即拉；未配 token 时按钮给出 `NO_TOKEN` 且零请求；
  - **原始存档是资产**：与既有 `output/.collector_cache/`（7 天 TTL）分层——存档**不过期**、
    默认放仓库之外的 `~/turtle_archive`、框架不主动删；每条存档带 token 指纹与来源摘要，
    以便将来分辨「这批数据是哪个权限档位拉的」；
  - **不重复拉**：同一（接口+参数+期次）已有存档即跳过；批次进度逐目标落盘，中断后只补未完成；
  - **缺口可识别**：把 `no_permission` / `rate_limited` 与 `empty` 区分开，产出机器可读缺口清单，
    租高权限账号时**只补缺口**。这一条直接修掉现状盲区：`financials.py:1083` 等处把权限错误
    写成「数据缺失 (接口可能无权限)」，使用者无法据此判断高权限能补到什么；
  - **复用既有实现**：协议、限流（`rate_limit`）、重试（`MAX_RETRIES`）、VIP 路由（`get_api_url` / `_VIP_MAP`）
