# REQ-011 一次性全量数据获取与统一原始数据仓

## 背景与问题

使用者的真实用法**已经写在 `REQ-009.4` 的背景里**：目前是只能拉很少数据的 Tushare 年包，
将来会短时间租用高积分账号，**一次把所需数据全部拉下来，然后长时间不再发起第二次拉取**。
`REQ-009.4` 为此做出了「批次 + 原始存档 + 缺口清单」三件套，但**只做到了一半**：

**问题 1：两条互不相干的取数链路，会重复花钱。**

| 链路 | 落盘位置 | 去重依据 | 缺口统计 |
|------|----------|----------|----------|
| `scripts/tushare_collector.py` | `output/<公司>/data_pack_market.md`（446 行 Markdown） | `output/.collector_cache/` **7 天 TTL**（`tushare_collector.py:72,82`） | 只有 `data_pack_market.md` 末尾一行「共 N/M 个数据板块成功获取」 |
| `REQ-009.4` 采集批次 | `~/turtle_archive/<TICKER>/<dataset>/<period>.json` + `manifest.jsonl` | 内容摘要，**永不过期** | 机器可读缺口清单 + `no_permission` / `rate_limited` / `empty` 分类 |

同一份远程数据可以被两条链路各拉一次；**`~/turtle_archive` 里的原始数据今天没有任何消费者**——
全仓 `grep`，除 `scripts/webui/archive/` 自己与 `scripts/webui/plugins/collect.py` 的三个**只读展示面板**外，
没有模块读它去生成任何产物。反过来 `data_pack_market.md` 只能联网生成，无法从存档重建。
于是「租一次高权限账号一口气拉全」拉下来的资产，**喂不到下游**；下游要的东西还得再联网拉一遍。

**问题 2：现在的「存储结构」既当给人看的报表，又当给程序读的数据源。**

`data_pack_market.md` 是小节化的 Markdown（§1…§17），下游程序在解析它：

- `scripts/results/prepare.py:311`、`scripts/value_analysis_engine.py:60`
- `scripts/webui/plugins/charts.py`（`find_section(text, "12.")`、`MONTH_SECTION = "年度行情汇总"`）

结果是「改个标题 = 改数据契约」：`charts.py` 里专门为「找不到小节 / 列对不上」写了两条降级路径
（`ArtifactMissing` / `ParseFailed`）。更麻烦的是**期次口径不是结构化的**：§3/§12 的表头是
`2026H1, 2026Q1, 2025H1, 2025Q1, 2025, 2024 …`——年度、半年、单季混在一行里，只靠列名区分。
GUI 侧因此出现了**把年报口径与季报口径画在同一条趋势线上**的问题
（走查报告 `docs/proposals/2026-09-28-console-pm-review.md` 的 `P-1`：营收从 2025 的 115,636
掉到 2025Q1 的 32,938 再回到 2025H1 的 61,776，这条「锯齿」是口径混用，不是经营波动）。

**问题 3：没有「一次点击拉全」的入口，也没有「我要维护哪些公司」这一层。**

- 采集只能走 CLI：`make gui-collect ARGS='--profile frugal --ticker 600887.SH --period 20260630 …'`；
  GUI 只有只读面板（`plugins/collect.py` 三个 `kind=table`）。
- 拉取目标由**手写参数**枚举（`archive/quota.py:targets_for_profile`），没有标的名单。
  「哪些公司在维护」今天只能看 `output/` 下**碰巧存在**哪些目录（`companies.py` 的 `COMPANY_MARKERS`）。
- 所以「一口气全拉」既没有一个按钮，也没有一条命令能完整表达；用户要自己拼 profile × ticker × period。

**问题 4：同一份数据有四个落盘位置，四种过期策略。**
`~/turtle_archive`（资产，不过期）· `output/.collector_cache/`（7 天）· `output/.webui_cache/`（派生，指纹失效）·
`output/<公司>/`（产物）。其中前三者都自称「缓存/存档」，用户无法判断「删掉哪个要重新花钱」。

## 目标

1. **有名单**：有一个显式维护的自选股清单决定「要维护哪些公司」，不再由目录是否碰巧存在决定。
2. **一次拉全**：一个动作（GUI 一次点击 / 一条 CLI）把清单内全部所需数据拉进**唯一**的原始数据仓，
   事前给得出预估，中途可中断续跑，绝不重复花钱。
3. **只拉一次**：原始仓是**唯一事实来源**；`data_pack_market.md` 等面向人的产物都能**纯离线**从仓里重建，
   且既有格式契约不变（下游脚本与既有测试不改）。
4. **缺口可见可补**：缺什么、为什么缺（无权限/限频/真为空/错误）可按标的、期次、数据集查询，并支持只补缺口。

## 验收标准

- **AC-1**：**标的宇宙（自选股清单）**——存在一个显式维护的清单（文件或仓表皆可），
  至少含 `ticker`、`显示名`、`市场`、`是否启用`、`所需数据档位`；CLI 与接口都能读；
  增删改标的不需要动代码（不改 `ENTRIES`、不改 `PROFILES` 常量即可生效）。
  「拉取全部」的目标集合由该清单推导，且**给定清单与期次范围能算出确定的目标总条数**（可断言）。
- **AC-2**：**一次动作启动全量拉取**——GUI 的一个动作或一条 CLI 子命令，能按「数据类别 × 标的 × 期次范围」
  枚举目标并启动**单个批次**；启动前给出**调用量预估**（目标条数、按档位分组的条数）并要求确认
  （`--yes` 可跳过，沿用 `REQ-009.4` 的 `AC-4.2` 语义）；执行期间可看到「已完成/总数」，可中断；
  全过程**不需要用户逐命令、逐路径地输入**。**给定清单 + 档位 → 预估条数**是可断言的确定值。
- **AC-3**：**统一原始仓（新存储结构）**——所有远程原始响应落进**一个**结构化仓，按
  (`标的`, `数据集`, `期次`, `参数`) **唯一**；每条记录至少带：抓取时间、接口名与入参、`result` 枚举
  （`ok`/`empty`/`no_permission`/`rate_limited`/`error`）、错误原文摘要、内容 sha256、字节数、
  token 指纹（sha256 前 8 位）、档位标签、框架版本；仓**可整体拷走**（单文件或单目录 + 显式清单），
  **不随 TTL 过期**，框架不主动删除，删除需显式动作 + 二次确认（沿用 `REQ-009.4` 的 `AC-4.3` 资产语义）。
  回滚/中断不得留下半条记录（写入是原子的）。
- **AC-4**：**期次口径是结构化字段**——每条与期次相关的记录都带口径信息（至少区分**年度 / 半年 / 单季 / 时点**，
  以及金额是**累计**还是**单期**）；下游不需要靠列名或小节标题猜口径。
  给定一份记录集，能按口径筛选出「仅年度」或「仅单季」两组序列（可断言）。
- **AC-5**：**离线重建派生产物**——在**禁网**（socket stub 为抛错）的环境下，能从原始仓重建
  `output/<公司>/data_pack_market.md`，且与联网路径产出的结构契约一致（既有下游按小节/表头解析仍成功，
  `scripts/results/prepare.py` 与 `scripts/value_analysis_engine.py` 的输入契约不变）；
  重建是**独立动作**，与「拉取」在 CLI 与界面上一分为二（不花钱 vs 花钱）。
- **AC-6**：**去重与断点续跑（收口既有语义）**——同一 (`数据集`, `标的`, `期次`, `参数`) 已有记录即跳过并计入
  「命中存档」；`--force` 才重拉；中断（Ctrl-C / 崩溃 / 取消）后重启同一批次只补未完成目标；
  同批次不允许并发；批次结束报告「新增请求 / 命中存档 / 失败 / 无权限」四类计数。
- **AC-7**：**缺口查询与只补缺口**——可查询「某标的 / 某期次 / 某数据集」的完备度与缺口原因，
  并支持以缺口为目标发起补齐批次（`REQ-009.4` 的 `--only-gaps` 语义并入本需求，不得回退）；
  补齐后完备度随之收敛。
- **AC-8**：**旧数据迁移**——`~/turtle_archive/` 的既有记录与 `output/.collector_cache/` 的既有条目
  有一条**一次性导入**路径（导入后旧路径停写或只读，不出现「同一份数据两处都在写」）；
  迁移可重复执行且幂等，迁移报告列出导入/跳过/冲突的条数。
- **AC-9**（实跑）：用**真实 token** 实跑并留档——① 一次全量拉取（记录预估与实际调用数、配额档位）；
  ② 中途中断后续跑（确认已完成目标未被重拉）；③ **断网**从仓重建 `data_pack_market.md` 并与联网产物对比；
  ④ 按缺口清单只补缺口。报告给出可复制命令、观察结果与本次发现的问题去处（不写 token 本身）。

## 范围

**包含**

- 自选股清单（标的宇宙）及其读写入口。
- 唯一的结构化原始数据仓：新的存储结构与迁移路径。
- 一次动作的全量拉取编排：预估、确认、进度、中断续跑、去重、缺口补齐。
- 期次口径的结构化表达（年度/半年/单季/时点、累计/单期）。
- 从仓**离线**重建面向人的产物（首期至少 `data_pack_market.md`）与图表所需的序列数据。
- 迁移 `~/turtle_archive/` 与 `output/.collector_cache/` 的既有数据。

**不包含**

- 新增数据源协议或新接口实现（继续**复用** `scripts/tushare_modules/`、`tushare_collector.py` 的
  客户端、限流、重试、VIP 路由）。
- 自动 / 定时 / 启动即拉（`REQ-009.4` 的 `AC-4.1` 手动边界不变，不得引入任何 scheduler）。
- GUI 的信息架构、任务式交互与视觉（属 `REQ-012`；本需求只提供数据与命令能力，
  界面侧最多做「只读展示 + 一个触发入口」的最小接线，或干脆留给 `REQ-012.4`）。
- 改动 `data_pack_market.md` 的既有格式契约、run-store 契约、报告命名（`REQ-002`/`003`/`004` 固定）。
- 删除存档、云端同步、多机共享、按标的的权限管理。
- SQLite 之外的检索服务、向量库、外部数据库。

## 约束与依赖

- **零新增依赖**：只允许 Python 标准库与仓库既有依赖。`sqlite3`、`json`、`hashlib`、`pathlib` 均属标准库；
  任何需要第三方包的方案（Parquet/Arrow/DuckDB/ORM）本期都不可选。
- **产物契约不变**：`data_pack_market.md` 是下游与既有测试的输入契约，本需求改的是**它从哪来**，
  不是**它长什么样**；重建产物必须让现有解析路径继续成功。
- **凭据不入仓**：token 只从环境变量 / `.env` 读取；仓里只有指纹与档位标签（沿用 `REQ-009.4` 的 `AC-4.7`）。
- **资产语义**：原始仓不过期、不主动删、可整体拷走；删除必须显式 + 二次确认（沿用 `AC-4.3`）。
- **手动边界**：联网只能由显式动作触发（沿用 `AC-4.1`）。
- **期次口径只有一处权威**：复用既有的 `scripts/periods.py`（`ARCHITECTURE.md` 已明写「期次标识由它统一定义」），
  `datalayer` **不得**自带第二套期次正则或月份映射。本需求只做两件小事：
  ① 往 `periods.py` 补 `end_date`（`20260630`）↔ 项目期次（`2026H1`）的换算；
  ② 把 `tushare_modules/assembly.py` 里私有的 `_yoy_period_label`（`20260630 → 2026H1`、`20121231 → 2012`）
  提升为 `periods.py` 的公开函数并改由它调用。这两处落在 `REQ-001`/`REQ-002` 的既有链路上，
  合入前必须跑 `REQ-006` 的全量回归。
- **与既有层的边界**：`datalayer`（买回来的、永不过期）与 `scripts/webui/datastore/`（算出来的、可失效）
  是两件事，不得互相接线；判据见 `docs/DATA_LAYER_PLAN.md` §3.2。
- **依赖**：`REQ-001`/`REQ-002`（报告发现与可比期，决定「期次范围」从哪来）、
  `REQ-009.4`（既有批次与存档实现，本需求在其上升级并**不得回退**其已验收语义）。
- **测试预算**：`REQ-009` 的 4 个 webui 测试文件已 **64/64 零余量**，本需求必须新开测试文件
  （规划 3 个）。仓库总预算经 owner 于 2026-09-28 批准由 48/1800 上调为
  **52 文件 / 2000 用例**（变更记录：`REQ-006` 的 `AC-7` 与任务 **T9**；实测落点 38/52、1653/2000）。
  **本次上调没有先做用例清理**，该欠账登记在 `ledger.md` 的「待登记想法（Inbox）」，
  须在下一次接近上限之前还掉；纪律不变：不得为了让新测试挤进预算而删断言或加 `skip`，
  各片按 `docs/DATA_LAYER_PLAN.md` §14.2 的预算写，不因为有余额就随便加。

### 2026-09-30 展示与测试诚实性（[PR #87](https://github.com/CHU-2002/Value_analysis_framework/pull/87)）

`AC-9` 真实 token 实跑留下的两条非阻断观察项（原登记在 `ledger.md` 的 Inbox）：

1. **断网重建的缺口现在会说出原因**：联网路径在失败时渲染「数据缺失（Tushare yc_cb 接口未授权；
   当前账号权限不足）」，重建早先只写「数据缺失」，把仓里记着的原因丢了。现在离线未命中时
   从仓里读出最近一次失败的原因（无权限 / 频率受限 / 接口错误），**用与联网路径同一种方式**

   而原用例因为跑它时模块早已被导入，永远看不到那一步——它是**蒙对的**。现在直接打桩
   `DataAccess._invoke`（唯一的远程调用点）令其抛错，外加 socket 兜底：真有人加了联网调用，
   用例立刻红。
