# REQ-014 控制台里的自选股清单维护（添加 / 从既有产物导入 / 移除）

## 背景与问题

`REQ-012`（控制台 2.0）的 `REQ-012.4` 数据页把**自选股清单**当成既成事实来消费：清单是拉取与
缺口计算的唯一依据，但**控制台里没有任何维护清单的入口**。事实与证据：

- `REQ-012` 的门② 独立验收**第二轮与第七轮两次登记**这一条：「删掉了命令，却没给替代的界面动作」
  （报告 [`docs/verification/2026-10-09-REQ-012-reverify.md`](../verification/2026-10-09-REQ-012-reverify.md)
  与 [`…-reverify6.md`](../verification/2026-10-09-REQ-012-reverify6.md)）。
- 清单为空时，数据页只能给文字说明——`scripts/webui/plugins/data_page.py` 的引导语现在是
  「登记清单目前属于数据层的准备工作（逐个登记，或从已经分析过的公司一次性导入），控制台里暂时
  还没有对应的入口」。
- 用户想跟踪一家新公司，只能离开界面去敲数据层 CLI（`python -m scripts.datalayer universe add …`），
  这正是 `REQ-012` 的 `AC-3`「不许把 CLI 命令/开关/路径推给用户」要消灭的老毛病。

**范围边界**：`REQ-012.4` 的范围是「**消费** `REQ-011` 的清单」，本条不修改 `REQ-012` 的任何已验收
条款——它是**新增能力**，按 [`README.md`](README.md) §7 单独登记编号（先 Issue #102，本条停在
`proposed`，等评审确认后再 `accepted`）。

## 目标

1. 让用户在控制台里**添加**要跟踪的公司，不用离开界面、不用敲命令。
2. 让老用户能**从既有产物一次性导入**清单（升级上来的主路径）。
3. 让用户能**移除**不再跟踪的公司，且**不动任何产物**（清单是跟踪范围，不是数据本身）。
4. 三个入口都走 `REQ-012.2` 的动作层，因此天生带上「标题 / 说明 / 禁用理由 / 执行前影响说明」，
   并受 `AC-3` 的文案禁则约束。

## 验收标准

- **AC-1**：数据页能**添加**一个标的（代码 + 简称）。给定 `600887.SH` / `600887` / 目录名别名三种写法，
  都能解析到同一家公司；添加成功后工作台、数据页、公司列表在同一页刷新内反映出来。
  判据：`POST` 动作 → `GET /api/v1/panels/data.universe` 的 `rows` 里出现该标的，且
  **没有任何远程请求**（动作声明的 `effects.network` 为 false、测试断言未触碰 token / 网络入口）。
- **AC-2**：数据页能**从既有产物导入**。给定产物目录，动作结果要给出「导入 N 家、跳过 M 家」，
  并对每个跳过项说明原因（没有 `record.json`、目录名不合约定、已在清单里…）。
  判据：同一目录导入两次，第二次不新增条目（幂等），且结果里的计数与清单实际条数一致。
- **AC-3**：数据页能**移除**一个标的，且**只改清单、不删产物**。
  判据：移除后 `data.universe` 不再有它，而同一家公司的数据包与 `record.json` **仍在**（逐文件存在性断言）。
- **AC-4**：三个入口的**面向用户文案**不含命令 / 开关 / 路径 / 接口路径（与 `REQ-012` 的 `AC-3`
  同一套措辞扫描判，判据落在**渲染后的 HTML** 与动作声明上）。
- **AC-5**：清单为空时的引导必须指向**界面上真实存在的入口**。
  判据：走查断言「引导里提到的入口，在同页面能找到一个对应的可点元素或动作卡」——这条正是
  `REQ-012` 门② 第七轮登记的非阻断项（引导指向不存在的入口）。
- **AC-6**：**实跑**：在真实产物目录上执行一次「从既有产物导入」，核对清单条数与导入结果一致；
  命令、环境与观察写进验收报告（`scripts/acceptance_gate.py` 强制「## 实跑记录」）。

## 子需求

本期整体交付与验收，不另拆子需求。

## 范围

- **做**：`scripts/webui/plugins/`（数据页与动作注册）、`datalayer.universe` 的写接口接线、
  三个动作的文案与禁用理由、走查断言（引导指向真实入口）、测试文件。
- **不做**：改动 `REQ-012` 的已验收条款；新建独立的「清单管理页」（先按动作层做，若评审认为需要页面再说）；
  批量编辑 / 导入导出文件（不在本期判据内）。

## 约束与依赖

- 依赖 `REQ-011` 的清单写接口（`datalayer.universe`）与 `REQ-012` 的动作层。
- 写清单是**本地、离线**操作，不带 `network` / `quota` 影响；文案里不许出现命令、开关、路径。
- 「移除」必须只是停止跟踪：产物是事实来源，不能因为清单变化被删。

## 手工自测清单

1. 空清单时打开数据页：引导里提到的入口在页面上找得到（可点）。
2. 添加 `600887.SH`、`600887`、`600887_伊利` 三种写法：都归到同一家公司，不产生重复条目。
3. 从一个含多份产物的目录导入两次：第二次「新增 0 家」。
4. 移除一家公司：清单里消失，产物目录逐文件仍在。
5. 三个动作在无 token / 网络不可用时都能执行（离线动作），文案不出现命令与路径。
