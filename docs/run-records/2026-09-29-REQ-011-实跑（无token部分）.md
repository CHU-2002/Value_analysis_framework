## 结论

1. **`AC-8` 成立（真实载荷）**：29 条真实台账 + 真实缓存文件全部进仓（53 条 / 6.7 MB），
   第二次执行 `导入 0 / 跳过 53`——幂等；冲突按设计**只报告不覆盖**。
2. **`AC-5` 成立（真实载荷）**：全程不联网，从仓重建出 22/23 个板块的产物，小节与表头契约不变，
   `§3` 表里是真实数字；重建是只读动作（`manifest.jsonl` 与记录数不变，由测试断言）。
3. **完备度口径的修正被真实数据证实**：真实仓里 `yc_cb` 是 `no_permission`（原文
   「抱歉，您没有接口(yc_cb)访问权限」），产物末尾写的是 `22/23 … 无权限 1`——**没有**像
   `REQ-006.1` 实跑时那样把无权限算成成功（当时尾部写 `14/14`）。
4. **4 条缺口都解释得清、且都是真实的**：
   - `income` / `balancesheet` 的 `report_type="6"`（母公司报表）：旧存档只拉过合并报表，
     §3P/§4P 因此没有料——新的 `data-pull` 会把 `report_type=1/6` 各拉一条（`registry.variants`）。
   - `fina_mainbz`：旧存档里 600887.SH 没有这个数据集。
   - `yc_cb`：旧存档里只有一条 `no_permission` 记录（不是「没拉过」）。
5. **两条冲突的来源**：`stock_basic_000858.SZ` / `stock_basic_600887.SH` 在
   `~/turtle_archive` 与 `output/.collector_cache/` 都有一份、且内容不同（两次调用的
   `fields=` 不同）。按设计「同键不同内容 = 冲突」报告出来，先导入的那份保留；
   要改成后者可用 `--force-import`（显式动作）。
