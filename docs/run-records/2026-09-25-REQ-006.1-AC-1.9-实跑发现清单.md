## F11（中~高）§16 总股数量级错误：标注「万股」实为「亿股」，差 10,001 倍
- 实测数据包 §16（两轮 run 完全相同，长期存在）：
  ```
  | 无限售质押 (万股) | 3.98 |
  | 有限售质押 (万股) | 0.00 |
  | 总股本 (万股)     | 63.25 |
  | 质押比例 (%)      | 6.29 |
  ```
- 反证（用 §1 自己的数据）：总市值 17,015,220.01 万元 ÷ 当前价 26.90 元 = **632,536 万股**
  = 63.25 亿股。即表里的 63.25 单位是**亿股**，标签却写「万股」→ 差 **10,001 倍**。
  质押比例 6.29% 也只有按亿股读才自洽（3.98 亿 / 63.25 亿 = 6.29%），所以整张表的绝对值都错了、
  只有比例是对的。
- 根因（可定位到行）：`scripts/tushare_modules/other_data.py:436-438` 对
  `unrest_pledge` / `rest_pledge` / `total_share` 都传了 `divider=1e4`，但 Tushare
  `pledge_stat` 的这三个字段**本来就是万股**，于是被二次除以 1 万变成亿股。
- **判定性实测（真实 token，原始输出）**：
  ```
  pledge_stat(ts_code="600887.SH", fields="...,unrest_pledge,rest_pledge,total_share,pledge_ratio")
    end_date=20260918  pledge_count=60  unrest_pledge=39775.1  rest_pledge=0.0
    total_share=632536.07  pledge_ratio=6.29
  ```
  而用 §1 自身数据反推：17,015,220.01 万元 ÷ 26.90 元 = 6,325,360,599 股 = **632,536.06 万股**
  —— 与接口的 `total_share` **完全吻合**，证明接口单位就是**万股**；
  且 `39775.1 / 632536.07 = 6.288%` 与接口自带的 `pledge_ratio = 6.29` 自洽。
  → 修法是**去掉 `divider=1e4`**（而不是改标签），并加一条用 §1 市值/价格反推股数的一致性测试。
- 影响：任何消费 §16 总股数的下游（市值校验、质押比例重算、每股指标、选股筛选）会差 10,000 倍；
  而它又与 `pledge_ratio`（接口直接给的百分比）并存，容易让人误以为「比例对所以总数也对」。
