## 需求编号

REQ-015（proposed，P1；尚未受理，不开始实现）

## 需求背景

2026-10-10 按 owner 请求担任产品经理与 QA，使用正式 main 88dc97f 的真实浏览器与隔离数据副本试用图表、报告、生成报告、数据获取和采集存档。

- 左侧五个分组标题集中在所有页面链接之前，标题不可点击、层级与链接脱离；公司内容、全局管理、执行动作平铺，用户难以判断入口。
- 股价图实际为年度最高/最低/年末收盘折线，缺真实蜡烛 K线、成交量/均线及日/月/季/年切换；没有与价格时间轴联动的历史 PE/PB 和百分位。营收和利润共轴，缺范围、缩放与数值核对。
- 当前公司已选伊利，生成报告仍要求手填代码，且无 agent/模型选择。更严重的是合法代码预检也被“报告动作只接受股票代码”阻断；清除全局公司后相同代码预检通过。这是 REQ-013.3 既有回归，单独登记维护，不用新 REQ 代替修复。
- 报告默认展示长篇定性报告，产物选择在正文之后。72 个产物混列，两个价值分析报告都显示“定性报告”，没有版本日期/最新标识；选中的旧报告正文日期为 2026-06-09，没有目录、文内查找或版本对比入口。
- 数据获取页展示已有记录完备度 22/23，但只补缺口预估 37 个目标，未解释分母范围。空仓时“没有缺口”与“原始仓还是空的”同时出现。真实采集 2026H1 仅补 2 个目标，退出 0、done、新增请求 2、失败 0；GUI 主视觉却仍是批次 ID、done/frugal/partial 和原始接口名。

## 期望方案

一个完整的“公司研究工作区”：选公司 → 看清数据能否用于分析 → 选择 agent/模型生成 → 直接阅读本次报告 → 在图表和历史版本中核对。

左侧一级入口为工作台/公司/任务；公司内用概览/行情与估值/报告/数据四个可点击页签，生成/更新/导出是内容旁的操作按钮。批次/原始存档与迭代记录保留在对应内容下。

拟拆五个可独立验收的子需求：REQ-015.1 标准 K线与估值联动时间轴；REQ-015.2 可配置报告生成；REQ-015.3 报告阅读与版本比较；REQ-015.4 采集过程与结果解释；REQ-015.5 公司研究导航与页面布局。

## 验收标准（草案）

- **AC-1**：四个工作步骤共享公司上下文；切换公司不会串读或串写，历史任务保留原标的；无公司/无数据时给可执行下一步。
- **AC-2**：真实 OHLC 蜡烛、成交量和 MA5/10/20/60；日/周/月/季/年实际聚合，共享范围/缩放/平移/光标的 PE(TTM)/PB 与历史百分位。显示周期、查看范围、分位窗口、财务口径分别控制；百分位只用截至各时点的有效日样本，显示覆盖/样本数；复权缺依据禁用，缺历史经数据页确认补齐，图形/表/导出一致。
- **AC-3**：生成前可选已接入的 Codex/Claude Code 和该 agent 的模型；明确区分已确认可用/未验证/不可用，所选配置传到真实执行并落任务记录，不修改 CLI 全局配置或静默换模型。
- **AC-4**：报告阅读器在正文前可选类型与版本，展示期次/生成时间/新鲜度，目录跳转、全文查找、历史比较及本次产物直达；正式发布与历史版本依据既有指针/台账，不凭文件名或 mtime 猜最新。
- **AC-5**：采集展示范围/预计请求/已完成目标/实际请求/缓存复用/失败类别；结果汇总新增数据、剩余缺口与分析影响，按同一计划口径解释完备度，给恢复或补缺口动作。
- **AC-6**：常用路径在 1440×900 与 1024×768 桌面可用；主内容无整页横向溢出，长表只在自身区域滚动，技术细节可展开且凭据永不展示；键盘可完成主要操作。
- **AC-7**（实跑）：独立 QA 用真实浏览器与沙箱存档逐条验证五块能力，至少一批真实采集和一次真实报告生成；截图、观察、命令、退出码、实际 agent/模型和产物归属齐备，缺陷修复必须有失败→通过对照。

- **AC-8**：一级入口与公司页签可点击、有选中态，键盘/刷新/前进后退一致；分组标题紧邻所属链接，不伪装导航；已选公司一键到图表/报告/数据，原始批次/迭代记录等既有能力仍可达。

完整判据与界面布局以[REQ-015 需求文档](https://github.com/CHU-2002/Value_analysis_framework/blob/main/docs/requirements/REQ-015-research-workspace-ux.md)为准；本 Issue 摘要不能覆盖该文档。
