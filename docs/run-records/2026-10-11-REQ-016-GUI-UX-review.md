## 角色判断

### 产品经理

- “公司范围”应只提供“已维护公司”和“全部A股”，由用户按维护清单或全市场选目标。当前公司上下文不应悄悄缩小全市场计划。
- 全市场计划先展示标的快照时间、股票数、数据档位/期次、数据组、请求预估与复用量，用户确认后才联网；进度和最终缺口应按公司与数据组阅读。
- 报告清单应首先展示供人阅读的报告与源材料；`run_manifest.json`、`latest.json`、`qualitative_input.json` 等内部状态/输入文件不应占据普通报告列表。
- 变化报告应先回答“发生了什么、影响多大、主要原因是什么、证据来自哪里、哪些仍不确定”。对伊利 H1，收入增长而归母净利下降是重要背离；报告材料中有资产减值合计约 24.56 亿元、其中商誉减值约 15.47 亿元，但不能把税前减值直接说成归母净利降幅的等值原因。应将其作为重大候选驱动并解释口径与待核实项。
- 正文应减少 `run`、`bundle`、`D7`、`selected_chars`、`max_evidence`、`prior_analysis` 等生成流水线词；这些信息可留在技术细节，不应盖过经营结论。


随后执行真实 Chromium 本地 GUI 走查：

```bash
.venv/bin/python scripts/gui_research_walkthrough.py \
  --base http://127.0.0.1:8877 \
  --out output/.live_req016/evidence
```

走查脚本退出码 **1**，观察 **80 项通过 68 项、失败 12 项**；`failures` 列表中的问题在两个视口各重复一次：

1. 日线/一年、缩放、图表执行三项：伊利本地没有日 OHLC，页面提示尚未采集日线，属于无数据场景；因此没有可缩放的蜡烛，也不能据此判断绘图实现失败。
2. 无报告/无数据下一步、重复标题 fixture 三项：脚本使用的 `000001.SZ` / `000002.SZ` fixture 不在当前本地公司清单中，所以这些断言没有进入预期页面，不能判为功能失败。

其余 68 项包含报告默认类型、历史版本选择、目录/搜索、公司上下文、采集取消零请求等检查。完整机器结果见本机沙箱 `output/.live_req016/evidence/observations.json`；本次没有为通过率修改断言或产品代码。
