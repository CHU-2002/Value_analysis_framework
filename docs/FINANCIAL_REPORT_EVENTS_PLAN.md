# 财报重大事项主动发现：实施设计

> 本文描述怎么实现 REQ-017；验收边界以 [`REQ-017`](requirements/REQ-017-financial-report-events.md) 为准。

## 设计目标

用户提供公司和报告期后，系统主动检查该期的财报和可取得的正式披露，提出重要问题候选，核对证据，再用普通中文说明“发生了什么、为何值得注意、数字意味着什么、什么仍无法确认”。用户不需要先知道“该查商誉”或“是否有更正”才能得到提示。

五粮液、伊利用于证明重点场景被覆盖；它们不是公司特例，也不把事件名或固定短语当成触发器。

## 处理流程

### 1. 建立材料与覆盖清单

- 收集当前期定期报告、前后可比期报告、报告附注及相关临时公告；在有可靠检索能力时补充交易所/证监会等正式文件。
- 每份材料保存公司代码、标题、披露日、所涉报告期、来源 URL/本地路径、获取状态、文档版本和页数。
- 解析报表、附注、管理层讨论与审计意见；保留页码、表号、科目、单位、正负号和原文片段。
- 在分析开始前形成“材料覆盖清单”，把未获取的报告、未解析页和无法识别的表格作为显式缺口。缺少附注不能被报告成“没有风险事项”。

### 2. 构造可核对的事实层

- 把原文数字整理为带单位与期间的事实记录，保存原始值、规范化值、所在表/页、合并或母公司口径、原披露/更正后状态。
- 仅对确定口径的数据计算同比、环比、利润率、现金流/利润比、周转变化、杠杆变化等；保留计算公式与输入事实的证据指针。
- 对追溯更正建立“原披露值 → 更正值 → 变化量”关系，避免把更正前后两版当成两个独立事实重复累计。
- 模型可以阅读完整章节并提出未结构化线索。结构化抽取和数值计算辅助它校验，不要求所有线索先命中某个固定指标。

### 3. 让模型提出发现候选

采用“广泛阅读 + 定向复核”的两轮方式：

1. **广泛阅读**：将材料覆盖清单、报告主要章节、关键表格/附注和跨期数据提供给模型，要求它主动寻找显著变化、口径变更、矛盾、背离、集中风险和无法解释的变化；对每个候选要求给出原文证据、涉及期间、影响范围和置信限制。提示词要求开放式分析，不把下方检查面伪装为穷尽清单。
2. **定向复核**：系统提供跨表勾稽、历史趋势和有根据的比率作为“建议复核点”，让模型判断是否构成事项、是否已在广泛阅读中发现、是否只是正常业务波动。规则信号只用于补漏和核对，不直接生成风险结论。

常见复核面包括利润与现金流差异、收入与应收/合同资产/存货变化、毛利率或费用率突变、商誉和资产减值、债务及流动性、非经常性损益、关联方与承诺、会计政策/估计变化、审计意见、前期更正及监管处理。这些是检查起点，不构成固定事件分类上限。

### 4. 验证并分级候选

每个候选先变成结构化记录：问题陈述、支持证据、反向证据、计算与口径、影响、来源可信度、缺口和建议置信级别。验证步骤：

- 检查公司代码、子公司、报告期和披露日期是否对应；历史事件与当前期分别记录。
- 回到原始页/表/公告逐条核对引文和数字；对模型计算的数字用事实层重新计算。
- 比较主表、附注、管理层说明和外部正式披露；证据冲突时并列呈现冲突，不让模型自行抹平。
- 区分“来源明确披露”“监管/法院认定”“公司解释”“模型推断”“未知”。只有前两者可作为相应权威事实陈述。
- 依据金额相对规模、持续期间、对利润/现金/偿债/可比性的影响、监管/审计性质及不确定性排序。报告先展示高影响且证据充分的事项；低置信候选降级为待核实或不展示，并记录排除原因供验收。
- 不因某项金额大就自动断言它解释全部利润变化；按税前/税后、归母/少数股东、合并/母公司等口径说明影响边界。

### 5. 写成面向普通读者的发现卡

每项优先发现用固定但精简的信息结构表达：

1. **发生了什么**：一句话结论和报告期。
2. **为什么值得关注**：对利润质量、资产价值、现金、债务、历史可比性或披露可信度的具体关系。
3. **证据与金额**：重要数值、单位、前后期间及来源定位。
4. **已知 / 推断 / 未知**：公司说法和官方认定原样归属；分析推断单独标识；缺少的税务、少数股东、现金实现等影响写明。
5. **不能推出什么**：例如一次会计更正并不自动证明舞弊，减值金额也不等于净利润降幅。

财会术语首次出现时用简短日常语言解释，并给出原始术语，方便读者回看报告。摘要优先呈现重大、可证实的内容；流水线过程和长篇原文放入可展开的证据区。

## 质量与回归验证

- 建立带来源定位的回归集：包括伊利 2026H1、五粮液更正公告、五粮液证监会决定，也包括不在提示词/规则中点名的其他公司和报告期。
- 先由不参与实现的人阅读原件，标注高重要性发现、事实证据、口径、合理不确定性和不得作出的结论；再运行系统核验召回与错误归因。
- 每次报告变更检查：重大线索是否进入摘要；数字及口径是否准确；引用是否落到原件；是否混淆主体或期间；是否把推断升级成事实；普通读者能否说清为何该事项重要。
- 测试模型输出时用确定的材料快照和模型配置，保存输入摘要、模型/提示版本、来源索引、结构化候选和最终报告，以便复现。CI 使用本地固定快照/mock，不依赖在线模型或外部数据源；真实源可用性按 REQ-017 实跑判据另验。
- 对遗漏的重大问题登记为需求维护任务/子需求并补入回归集；不得只在提示词临时加入公司名来让单个案例通过。

## 风险与处理

| 风险 | 处理方式 |
|------|----------|
| 报告或附件过长，模型漏读 | 记录完整覆盖清单；分章节分析后做跨章节综合；未覆盖处显式报缺口 |
| OCR、表格单位或负号解析错误 | 保存原页定位；关键金额回到原表复核；不同解析结果冲突时不下确定结论 |
| 把相关性讲成因果 | 逐项区分事实、公司解释和推断；说明其他影响因素及尚缺证据 |
| 把风险提示写成舞弊指控 | 舞弊/违法定性需权威决定；其余用中性描述并说明尚未认定 |
| 固定清单只能识别已知案例 | 保留开放式模型阅读；用未点名案例和独立盲测评估新增发现能力 |
| 低价值告警淹没重点 | 按金额、持续性、影响、证据强弱和不确定性排序，低优先级内容折叠并说明理由 |
| 来源更新或更正导致事实过时 | 记录抓取/披露时间和版本；把更正视作新版本并链接前后差异，不覆盖历史来源 |
