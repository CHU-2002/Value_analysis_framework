## 一、需求图景：做完之后你能做什么

### 1.1 一句话

> 你不再需要背命令行。打开一个本地网页，**这个项目能做的事全是一排按钮**；
> 数字有图看，报告点开就读，每次分析/更新改了什么结论按时间线排好；
> 而**联网拉数据这件事，只在你说的时候才发生**——趁短租的高权限账号，一次拉全，然后长期不拉。

### 1.2 它由四块拼成（交付顺序就是下面的顺序）

| 顺序 | 编号 | 你得到什么（大白话） | 状态 |
|------|------|----------------------|------|
| **1** | `REQ-009.3` | **地基**：一个能跑起来的小服务 + 一套「以后加功能不用动地基」的框架 + 本地数据仓库（算出来的数据存着，不重复算） | `accepted` |
| **2** | `REQ-009.4` | **采集与存档**：手动按一下就开始拉数据，**拉过的绝不重拉**，原始数据永久存下来，**缺什么一目了然** | `accepted` |
| **3** | `REQ-009.1` | **按钮**：项目里全部 14 个入口 + 迭代台账 6 个子命令 + 定性管线 4 步，全部变成按钮，点了能看到运行状态、退出码和日志 | `accepted` |
| **4** | `REQ-009.2` | **看东西**：3 类股票图 + 报告在线阅读 + 迭代记录时间线（可切公司/期次/run） | `accepted` |
| 收口 | `REQ-009` | 文档、`make gui` 启动命令、**实跑一遍**并留档 | `accepted` |

### 1.3 逐项说明（你能亲手验证的东西）

**① 一屏看全项目能做什么**
左侧一栏按用途分组（取数 / 分析 / 估值 / 组合 / 选股 / 报告 / 迭代台账），每项就是一个按钮。
点下去看得到：实际跑了哪条命令、进行到哪了、退出码是几、日志最后几行。

**② 图表（首版 3 类，数据全部来自你本地已有的文件，断网也能看）**

| 图 | 看什么 | 数据从哪来 |
|---|---|---|
| 年度股价走势 | 最高 / 最低 / 年末收盘，11 年 | 已落盘的 `data_pack_market.md` §11 |
| 关键财务指标趋势 | ROE / 毛利率 / 净利率 / 资产负债率，9 个期次 | §12 |
| 营收 vs 归母净利润 | 按期次对比的柱状 | §3 合并利润表 |

鼠标悬停能看到具体数值。**不做**K 线缩放、几十种图表皮肤那种花活——这是「不装第三方图表库」的代价，我认了。

**③ 报告在线阅读**
定性分析报告、变化报告、估值结果、买卖计划、数据包、PDF 都能列出来，点开就在页面里读（标题、列表、表格正常显示），
不用先转 HTML。报告里的脚本会被转义，**不会**因为报告内容把你页面搞坏。

**④ 迭代记录（你特别要的那个）**
按时间**倒序**列出这家公司的每一次分析：run 编号、类型（首次/增量更新）、时间、替换了哪一次、
覆盖哪些期次、用的框架指纹，以及**这次相对上一次改了哪些结论**（`conclusions_changed`）。
当前生效的那次会标出来；如果下游估值/买卖计划已经过期，页面上会显眼提示。

**⑤ 采集与存档（按你的预算策略设计）**

| 你的处境 | 界面上的行为 |
|---|---|
| 年包只有很少配额 | 选 `frugal`（省着拉）：只拉必需板块 + 最新期次 |
| 短租了高积分账号 | 选 `bulk`（一次拉全）：全板块 × 全期次 × 全标的，**但按下去之前先告诉你「预计要发多少次请求」** |
| 拉完要长期不拉 | 原始数据**永久存档**（默认存在仓库之外的 `~/turtle_archive`），不像现有缓存 7 天就过期 |
| 不想重复烧配额 | 已经拉过的一律**自动跳过**；跑到一半断了、重启**只补没跑完的**；同一次不许并发跑两遍 |
| 想知道还缺什么 | **缺口清单**：哪一项没拉到、是「没权限」还是「真没数据」、接口原文报错是什么；完备度如 `12/14` |
| 以后再租高权限补 | 按缺口清单**只补缺口**，不动已完成的部分 |

**把你现在的一个盲区修掉**：现在代码抓到权限错误，一律写成「数据缺失 (接口可能无权限)」——
你根本分不清是「没权限」还是「真没数据」，也就没法判断「再租一个高权限账号能补到什么」。
这一条被写成验收标准（AC-4.5）要求修掉。

**⑥ 安全边界（不做成"随便都能跑"）**

- 只监听本机（`127.0.0.1`），**不提供**任何把它暴露到局域网的配置项；
- 没有「随便输个命令」的输入框：只能点白名单里的按钮、填表单参数，**不经过 shell**；
- 文件只能读 `output/` 里的东西，`../` 之类的路径穿越一律拒绝；
- 页面上**看不到 token**，日志里也会被脱敏；存档里只记 token 指纹和你自己填的档位标签。

**⑦ 可扩展（这条是你要求"最重要的事"）**
将来你提新的 GUI 需求——新页面、新图表类型（K 线、热力图）、新数据源、新按键、新任务——
**只加一个"插件"文件，不改地基**。这条不是口号，有专门的验收判据：
测试会往插件目录塞一个演示功能，断言它**自动出现在界面和接口上**，同时断言地基文件一个字节都没被改。

### 1.4 明确不做（免得以后扯皮）

| 不做 | 为什么 |
|---|---|
| 远程访问、多人使用、登录鉴权 | 属安全边界。将来要做得**另开一条需求**，连带鉴权和防护一起设计，不是改个配置 |
| 自动 / 定时 / 启动就采集 | 配额会被悄悄烧掉。联网必须由你按 |
| 在面板里改产物或编辑报告 | 本期只读优先；要写还是走既有脚本 |
| 新增数据源接口、改既有数据格式 | 采集是**复用**现有取数代码，不改协议、不改 `data_pack_market.md` 的产出 |
| 实时行情、交易下单 | 与本期目标无关，风险也高 |
| 云端同步 / 多机共享存档 | 本期只做本地存档；备份方式是把存档目录自己拷走 |

## 二、方案设计（人话版）

### 2.1 一张图

```
   你的浏览器（本地网页）
        │  只读数据、看图表、点按钮
        ▼
   一个只监听本机的小服务  ← Python 自带零件，不用装任何新软件
        ├── 地基：路由、错误处理、安全检查、任务调度、数据仓库
        ├── 插件：按钮、图表、报告、迭代记录、采集  ← 功能都在这层，可插拔
        └── 点按钮 = 调你项目里**原有的脚本**（不是另写一套）
        │
        ▼
   你磁盘上已有的产物：output/…（报告、数据包、迭代台账）
        ▲
        └── 只有你按「采集」时才联网（Tushare），结果存进永久存档
```

### 2.2 三个关键决策与理由

**决策一：不装任何新软件（零新增依赖）**
用 Python 自带的零件 + 手写一个网页。代价：界面朴素、图表只有折线/柱状。
好处：装完就能跑、断网可用、**CI 不被拖慢、测试预算不被顶破**。
（另外两个方案——专业前端框架、Streamlit——都会新增依赖并冲击 CI 门禁，所以否掉。）

**决策二：地基和功能分开（插件式）**
把「页面/图表/按钮」都做成可插拔的模块。理由：你会不断加需求，
如果每次加功能都要改地基，改到第五个需求时地基就烂了，而且每次改动无法独立评审。

**决策三：数据分三层，各管各的过期策略**（这是你"避免每次远程拉"的正解）

| 层 | 是什么 | 过期策略 | 删了会怎样 |
|---|---|---|---|
| **买来的** | 远程接口的原始响应（花钱换的） | **永不过期** | **要重新花钱拉** → 框架不主动删，删除要二次确认 |
| **算出来的** | 图表序列、报告索引、迭代时间线（从本地产物解析） | 源文件变了就自动重算 | 只是变慢，随时能重算 |
| **现读的** | 打开页面时临时用一下 | 请求结束就释放 | 无影响 |

一句话：**"买来的"和"算出来的"必须分开**——前者过期就意味着重新花钱，绝不能像普通缓存那样 7 天清一次。

### 2.3 联网边界（写死，不靠自觉）

| 动作 | 联网吗 | 谁触发 |
|---|---|---|
| 打开页面、看图、读报告、看迭代记录 | **不联网** | 你打开页面 |
| 算出来的数据过期重算 | **不联网** | 框架自动 |
| 采集数据 | **联网** | **只能你按按钮 / 跑命令**；没有定时器、没有启动就拉、没有打开页面就拉 |
| 显示"数据是多久以前的" | **不联网** | 页面上有个徽标告诉你数据生成时间 |

页面上「刷新视图」（不花钱）和「重新采集」（花钱）是**两个不同的按钮**，不会混。

## 三、预计工作方式

### 3.1 我们怎么一步步走

| 步 | 干什么 | 做完你能看到 | 大约规模 |
|----|--------|--------------|----------|
| 0 | **先合掉需求登记 PR #41**（需求+设计定稿） | 需求台账里 REQ-009 定稿 | 已就绪，等你点头 |
| 0.5 | **处理测试预算**（见 3.3） | 门禁有余量，不至于后面卡死 | 小 |
| 1 | 实现 `REQ-009.3` **框架** | 跑 `make gui` 能打开一个空壳面板；加法演示证明了「加功能不改地基」 | **全项目最大的一次改动**（约 15 个文件 + 1 个测试文件） |
| 2 | 实现 `REQ-009.4` **采集与存档** | 界面上出现采集按钮、调用量预估、批次进度、缺口清单 | 中等（约 7 个文件 + 1 个测试文件） |
| 3 | 实现 `REQ-009.1` **按钮** | 14 个入口全部可点，能看到状态和日志 | 小（约 2 个文件 + 1 个测试文件） |
| 4 | 实现 `REQ-009.2` **视图** | 3 类图 + 报告阅读 + 迭代时间线 | 中等（插件 + 前端渲染 + 1 个测试文件） |
| 5 | 收口 | README/CHANGELOG、`make gui`、**实跑记录** | 小 |

每一步都是一条独立分支 + 一个 PR，做完在**你机器上跑起来给你看**，你觉得不对可以直接提。
**不会一次性糊一大堆代码然后让你一次验收。**

### 3.2 分工：什么是我定，什么是你定

| 事项 | 谁定 | 说明 |
|------|------|------|
| 代码怎么写、测试怎么测、门禁怎么过 | **我** | 你不需要看这些 |
| 需求编号受理 | **你**（已拍板 REQ-009） | 仓库规矩：新编号是需求决策 |
| **改验收标准（做什么、做到什么程度）** | **你** | 我会把原条款、原因、新条款记进「变更记录」 |
| **动测试预算 / 放宽门禁** | **你** | 我不会为了让门禁变绿自己放宽 |
| **实跑**（真实 token、真实数据源） | **你**（或持 token 的执行者） | CI 全是假数据，测不到权限报错、限流、真实载荷 |
| 独立验收报告 | **独立的一方** | 仓库规矩：写代码的人不能给自己发合格证 |

### 3.3 现在的三个卡点（必须你拍板）

1. **PR #41 还没合**（需求登记）。后面所有代码 PR 都应该从最新的 `main` 切出来，
   所以建议先合它。
2. **测试预算快满了**：仓库有硬上限「测试文件 ≤40、用例 ≤1600」，现在是 **33/40、1522/1600**。
   我这次规划的四块测试加起来 64 条 → 会到 **1586/1600（99.1%）、37/40，只剩 14 条余量**。
   仓库自己的规矩是「接近上限先清理，不要调高上限」。所以要么：
   - **（推荐）** 先做一次**用例清理**（合并重复用例、删掉只复述实现的测试）腾出余量；或
   - 你明确**批准上调上限**（我会写明理由、同步登记表）。
3. **`REQ-009.4` 的验收需要你实跑**（真实 token）。到那一步我会给你一份可复制的命令清单，
   你按着跑一遍，我把它记进「实跑记录」。

### 3.4 每步你怎么验收（不用看代码）

| 步 | 你做这一件事就够 |
|----|------------------|
| 框架 | 跑 `make gui`，打开页面：能看到空壳面板、导航、示例数据面板；故意改坏一个插件，页面仍能打开（说明隔离生效） |
| 采集 | 不配 token 点采集 → 看到明确提示且没有任何请求；配上 token 后先看调用量预估，确认后跑一小批；断掉再重启，确认没重拉 |
| 按钮 | 随便点 3 个按钮，比对命令行与你以前手敲的一致，能看到退出码和日志 |
| 视图 | 打开 600887：看到 3 类图、报告、2 次 run 的时间线（首次 → 增量更新）和结论变化 |
| 收口 | 断网刷新一遍，确认图表报告照常显示（证明不联网也能用） |

### 3.5 我需要你介入的次数

大致 **6 次**：合 #41、定预算处理方式、框架跑起来给你看、采集跑起来给你看（含你实跑）、按钮+视图跑给你看、收口验收。
其余时间我自己跑门禁（每步都要求本地 `make verify` + CI 全绿），不占用你。

## 四、诚实的取舍与风险

| 事 | 实话 |
|----|------|
| 界面好看程度 | **朴素**，像内部工具后台。想要漂亮就得引入前端框架，代价是 CI 变重、依赖变多 |
| 图表能力 | 折线/柱状 + 悬停数值。K 线缩放、专业皮肤**不做** |
| 第 2 步（采集）最需要你配合 | 它的价值全在真实 token 上，CI 测不了；我会把命令写清楚，但跑要你来 |
| 存档要自己备份 | 存在仓库外的 `~/turtle_archive`，框架不主动删；**但机器坏了就没了**，重要的话自己拷一份 |
| 测试预算紧 | 见 3.3，不解决的话后面每加一个测试都难受 |
| 第 1 步改动最大 | 框架是地基，返工最贵。所以我先做它，并且用它自己的验收判据（"加功能不改地基"）来证明它立住了 |
