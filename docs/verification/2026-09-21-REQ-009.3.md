### 新发现的问题

| 编号 | 严重程度 | 现象（可复现） | 建议去处 |
|------|----------|----------------|----------|
| **P1** | 低~中（**取决于 token 形态**） | **脱敏作用在「已序列化的文本」上，凭据的转义形态会绕过 `replace`**。`_send` 拿到的已经是 `envelope.dumps` 产出的 JSON 或 `render_panel_error` 产出的 HTML，而 `json.dumps` 会把 `"`→`\"`、`\`→`\\`，`html.escape` 会把 `&`→`&amp;`、`"`→`&quot;` 等。于是凭据里含这些字符时，响应体里出现的是**转义后的真值**，`str.replace(secret, "***")` 匹配不到。实测（`TUSHARE_TOKEN='ab"cd12345678'`）：`GET /api/v1/pages/leak.page` 的降级卡片里留下 `token=ab\"cd12345678`；`GET /api/v1/panels/leak.tokenparam?company=…` 的 `error.message` 里留下 `实际收到 'ab\"cd12345678'`，**JSON 解析后就是明文 token**；`TUSHARE_TOKEN='ab&cd12345678'` 时 HTML 里留下 `ab&amp;cd12345678`。`TUSHARE_API_URL`/`HTTP_PROXY` 若带查询串或带 `&`/`"` 的代理口令同样命中。**注意：AC-3.7 的字面判据是「用 `TUSHARE_TOKEN` 的实际值做替换」，而真实 Tushare token 是字母数字/十六进制串（不含上述字符）——该形态下我逐条实测全部通过，因此本轮不据此判 AC-3.7 不成立。** | **缺陷（低~中，建议本切片或紧随其后修）**：`redact` 改在**值层**做（`envelope.dumps` 前遍历 payload，或对 `_send` 同时匹配 raw/JSON-escaped/HTML-escaped 三种形态），并补一条「token 含 `"`/`&` 时响应仍不含可还原真值」的契约测试。**判定规则**：若团队的 token/代理 URL 形态**可能**含 `"` `\` `&` `<` `>` `'` 之一，P1 升级为**阻断**；若确认只可能是 `[0-9a-zA-Z]`，可登记为低并排期 |
