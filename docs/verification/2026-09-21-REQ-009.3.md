### AC-3.3 不成立（阻断）

- **现象**：`render="client"` 且只有 `endpoint`、没有 `provider` 的面板（图表的生产形态），浏览器端
  **永远不去请求 `endpoint`**，面板显示「暂无数据」，不渲染 canvas。用真实 `app.js` 驱动真实服务的
  实测 `fetchCalls` 里根本没有该 endpoint 的请求。
- **复现步骤**：
  1. 写一个仓库外插件，注册 `PanelSpec(id="demo.chart", kind="chart", render="client",
     endpoint="/api/v1/demo/chart")`（不设 provider）与对应路由，用 `--plugins` 加载并 `--port 0` 起服务；
  2. `GET /api/v1/pages/demo.page` 确认 `demo.chart` 的载荷是 `"render":"client"`、`"endpoint":"/api/v1/demo/chart"`、`"data":null`；
  3. 用真实 `app.js`（仅把两行绝对 import 改为相对）在 Node + 最小 DOM stub 下 `openPage("demo.page")`，
     记录 `fetch` 调用与面板 DOM；
  4. 观察：`fetchCalls` 无 `/api/v1/demo/chart`；`demo.chart` 的 body 文本为「暂无数据」、canvas 数 0。
- **影响范围**：REQ-009.2（报告浏览、3 类图表、迭代台账视图）全部是客户端渲染面板，按当前框架
  **一个都画不出来**；`form`/`jobs` 这两个客户端 kind 同样受影响（它们目前还被 `app.js` 映射到
  fallback 渲染器）。这是框架切片必须先还的债，否则后续每个 GUI 需求都要绕。
- **建议处理**：修 `render/panels.py` 的 `payload["data"]`（无 provider 时不写 `data` 键，或改成
  `undefined` 语义）**或** 修 `app.js` 的判断（`data == null`）。二者取一，并补一条**端到端**契约
  测试：客户端 kind 的面板在无 provider 时必须真的发起 endpoint 请求。修完请连 D3 一并处理
  （页面不该因为一个面板缺参/抛错而整体 5xx/4xx），因为这两条一起决定 REQ-009.2 能不能开工。
