### 第三条 `wait_history_file`（CI 时序依赖）—— 结论：**不成立**（F1）

实现者称：`wait_job` 看到内存 `finished` 就返回、历史文件可能还差一拍，改成「等历史文件落盘」后
「**不再依赖调度时序**」。我的三步观察：

**P1 · 历史文件什么时候出现**（`/tmp/req012_r8_history_race.py`，不 patch 任何东西）：

```
submit 返回后               : 存在且可解析 status=running     ← 文件在**提交时**就已落盘
wait_job 看到 finished 后   : 存在且可解析 status=finished
wait_history_file 返回后    : 存在且可解析 status=finished
```

以及代码（`scripts/webui/core/jobs.py`）：`submit()` 在 `_launch()` **之前**就调用 `_write_history()`
（所以文件从提交起就存在），`_finish()` 是**先设内存状态、后写文件**，写入用 `write_text()`（**先 truncate 再写**，
非原子），而 `_load_history()` 对 `json.JSONDecodeError` 是**静默跳过**。
⇒ `wait_history_file` 等的是 `path.exists()`，而它在**第一次写**之后恒为真 → **它并不会等最后一次写入落地**。

**P2 · 慢写下复现 CI 的 `assert 0 >= 1`**（把 `_write_history` 换成「truncate → 等 0.4s → 写内容」，
即慢盘/高负载 CI 的等价物，其余流程与用例完全一致）：

```
wait_job 看到 finished 后   : 存在但为空 | 内存 status = finished
wait_history_file 返回后    : 存在但为空 （注意：写还在飞）
重启后的 runner 读到        : JobNotFound（任务丢失）→ 即 list count = 0 → `assert 0 >= 1`
```

**P3 · 连跑 15 次全绿**（用例本身在本地稳定，说明这条不是靠重复跑能观察到的）：

```
15 × `.venv/bin/python -m pytest -q tests/test_console_actions.py::test_job_history_round_trips_through_a_restart`
→ 1 passed in {1.03, 1.37, 0.73, 0.87, 0.75, 0.59, 0.63, 0.56, 0.62, 0.80, 0.52, 0.58, 0.46, 0.62, 0.46}s（15/15 通过）
```

⇒ 我的结论：**这条「修复」在结构与实测上都不是等待点**（文件早已存在，`exists()` 立即为真），
CI 上那条 `assert 0 >= 1`（截断中的文件被读走 → 解析失败 → 静默跳过 → 0 条）**仍然可达**，
我在受控慢写下确定性复现了它。判据本身没有放宽（仍然断言历史读得回来），但**「不再依赖时序」这个声明不成立**。
详见「未通过 / 存疑项」F1。

## 我自己设计的受控实验（X1 / X2）：前置断言到底是不是活的

洞① 的修复是**两件东西**：夹具（让 `estimate` 有内容）+ 一条前置断言（`assert any(estimate)`）。
实现者自证的是「注入会判红」，但**没有人验证过那条断言本身有没有用**——如果它是死的，
夹具一旦回退，判据又会静默失效。所以我自己设计了这组实验（临时改 `tests/test_console_actions.py`，
两次都逐位还原）：

**X1：把夹具退回修复前的状态（不建仓、不建清单），保留断言** → 期望断言按预期炸响：

```
E  AssertionError: 夹具必须让 estimate 有内容，否则 estimate.detail 不在扫描范围内（判据形同不存在）
E  assert False
→ 1 failed
```

**X2：在 X1 的基础上再去掉断言，并重新注入 `--r8-estimate-inject`** → 期望**静默判绿**（复现原洞）：

```
.                                                                        [100%]
1 passed          ← 注入的违规文案在载荷里，用例却绿了——这就是第七轮那条洞
```

⇒ 结论：**断言是活的、并且是承重的**——有它时夹具回退会立刻炸响（不会退化成「判据形同不存在」）；
没它时同一条注入会静默通过。夹具 + 断言这一对确实把洞堵上了，不是「看起来修了」。

  `JobNotFound`（count = 0）。**这是确定性复现，不是偶发**。
- **影响**：CI 少见的假失败会复现；更值得登记的是**产品侧**的窄窗口——面板重启恰好与最后一次历史写入重叠时，
  那条任务会从历史里静默消失（`AC-2.3` 的「任务历史落盘后读得回来」在正常路径上成立，这个窗口没有覆盖）。
