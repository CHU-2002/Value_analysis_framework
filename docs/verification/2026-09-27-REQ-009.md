### 本轮新发现：`N4`（**非阻断**，建议登记，可与 `V3` 一起处理）

**现象一（500）：公司目录里若有「`stat()` 会以非 `ENOENT` 失败」的子条目，产物索引直接 500。**

```bash
# 临时根 /tmp/v8_out 下造两个公司目录（都不碰仓库 output/）
ln -s "$(python3 -c "print('a'*1000)")" /tmp/v8_out/company2/bad_link     # 目标超长 -> ENAMETOOLONG
mkdir /tmp/v8_locked && printf '# s\n' > /tmp/v8_locked/secret.md && chmod 000 /tmp/v8_locked
ln -s /tmp/v8_locked/secret.md /tmp/v8_out/company4/link_to_locked        # 目标目录不可进入 -> EACCES

curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' 'http://127.0.0.1:8811/api/v1/companies/company2/artifacts'  # 500
curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' 'http://127.0.0.1:8811/api/v1/companies/company4/artifacts'  # 500
curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' 'http://127.0.0.1:8811/api/v1/pages/report?company=company2'  # 200 + 逐面板降级卡
```

服务端原始 traceback 的根因（我从日志里取的）：

```text
File "scripts/webui/datastore/datasets.py", line 156, in _resolve_sources
    existing = [path for path in found if path.is_file()]
File "…/python3.12/pathlib.py", line 892, in is_file
    return S_ISREG(self.stat().st_mode)
OSError: [Errno 63] File name too long: '/private/tmp/v8_out/sneaky_single'
（EACCES 那一例同帧，errno 13；两者都不被 `pathlib` 的 `_ignore_error` 吞掉）
```

要点：这与 `V7`/`V8` 修的不是同一层——`safe_join` 只探测**被请求的那一个路径**，
看不见**目录里的子条目**；而 `pathlib` 只忽略 `ENOENT`/`ENOTDIR`/`EBADF`/`ELOOP`
（我实测：公司目录里放一个**自环**子链接 → `200`，正是 `ELOOP` 被忽略；放一个目标超长的链接
→ `500`）。要触发它，需要 `output/<公司>/` 里存在这类条目（例如一条指向很长路径的便利链接，
或指向不可进入目录的链接）。

**现象二（观察）：`companies/{dir}` 不校验「是不是公司目录」，`dir` 归一化到 output 根时会把
根下的顶层文件当成「某公司的产物」列出。**

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8813/api/v1/companies/%2e/artifacts'                              # 200，dir="."，count=5
curl -s --noproxy '*' 'http://127.0.0.1:8813/api/v1/companies/600887_%E4%BC%8A%E5%88%A9%2f../artifacts'   # 200，dir="600887_伊利/.."
```

`output/` 顶层的 `data_pack_market.md`、`screener_full_result.csv`、`screener_full_result.html`、
`screener_short_result.csv` 等会被列出来。**这仍在 `output/` 之内**（jail 的判定是
`resolve()` 后仍在 output 子树内、含根本身，与 `AC-3.7` 的措辞一致），没有越界；但与
「按公司列出产物」的语义不符，也是我在临时根上撞出「现象一」的那条路径。建议要么显式拒绝
`base == output_root`（只接受真正的公司目录），要么把它当作「output 根视图」写进文档。

**为什么非阻断**：`N4` 不越权、不读树外内容、不崩服务；响应只有请求 id，堆栈只进日志；
`pages/*` 层仍能逐面板降级成 200 + warnings（用户看到的是降级卡，不是白屏）；
它属 `V3`（坏符号链接连坐整页）的同族——若按 `V3` 的「跳过坏条目 + `warnings` 点名」处理，
`N4` 现象一会一并消失。建议修法：`datastore._resolve_sources` 的 `is_file()` 过滤（以及任何
枚举期 `stat`）外层加 `try/except OSError`，非 `ENOENT`/`ENOTDIR` 就跳过并记 warning；
或改用 `os.scandir()` + `entry.is_file(follow_symlinks=False)`。
