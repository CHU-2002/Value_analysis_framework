### 新发现 N2：无法解析的路径片段仍然 500（**非越权**，建议登记 `V7`）

`%00` 修好了，但 `V6` 提交说明/登记里那句「**符号链接环、超长路径同样归到 `PathOutsideRoot`
→ 403**」**没有端到端成立**——我实测这两类输入依然 500。它们同属「`safe_join` 的兜底没接住」
这一族，但成因不同，分开写：

**N2a · 符号链接环 → `RuntimeError`（不是 `OSError`）→ 500**

```bash
mkdir -p /tmp/v6_out && ln -s /tmp/v6_out/loop_b /tmp/v6_out/loop_a && ln -s /tmp/v6_out/loop_a /tmp/v6_out/loop_b
mkdir -p /tmp/v6_arch/batches && ln -s /tmp/v6_arch/batches/lb.json /tmp/v6_arch/batches/la.json && ln -s /tmp/v6_arch/batches/la.json /tmp/v6_arch/batches/lb.json
WEBUI_OUTPUT_ROOT=/tmp/v6_out WEBUI_ARCHIVE_ROOT=/tmp/v6_arch \
  .venv/bin/python -m scripts.webui --port 8807 --no-browser

for p in /api/v1/companies/loop_a/artifacts /api/v1/companies/loop_a/report /api/v1/companies/loop_a/charts \
         /api/v1/companies/loop_a/runs /api/v1/collect/batches/la \
         /api/v1/panels/companies.artifacts?company=loop_a ; do
  curl -s -o /dev/null -w "$p -> %{http_code}\n" --noproxy '*' "http://127.0.0.1:8807$p"
done
# 全部 500 INTERNAL；/api/v1/pages/report?company=loop_a -> 200（逐面板降级卡）
# /api/v1/collect/batches/ok（同目录下的正常文件）-> 200
```

原始 traceback 的根因（我取的服务端日志）：

```text
  File "scripts/webui/core/security.py", line 71, in safe_join
    resolved = candidate.resolve()
  File "…/python3.12/pathlib.py", line 1252, in resolve
    check_eloop(e)
  File "…/python3.12/pathlib.py", line 1237, in check_eloop
    raise RuntimeError("Symlink loop from %r" % e.filename)
RuntimeError: Symlink loop from '/private/tmp/v6_out/loop_a'
```

关键事实：CPython 3.12 的 `Path.resolve()` 把 `OSError(ELOOP)` 在 `pathlib.check_eloop` 里
**改抛 `RuntimeError`**，而 `V6` 新加的兜底只写了 `except (OSError, ValueError)`，所以环逃过兜底、
冒到 HTTP 面成 500。

**N2b · 超长片段 → `resolve()` 不抛，ENAMETOOLONG 在下游才出现 → 500**

```bash
# 单片段长度边界（本机 APFS）：255 及以下正常 404，256 起 500
curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' \
  "http://127.0.0.1:8805/api/v1/companies/$(python3 -c "print('a'*255)")/artifacts"   # 404
curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' \
  "http://127.0.0.1:8805/api/v1/companies/$(python3 -c "print('a'*256)")/artifacts"   # 500
```

命中面（300 字符片段）：`companies/{dir}/artifacts`、`/report`、`/charts`、`/runs` 全 **500**，
`collect/batches/{batch_id}` **500**，`panels/{companies.artifacts,charts.metrics,runs.timeline}?company=`
**500**；`pages/*?company=` 仍是 200 + 降级卡。总路径超限同理：`60 段 × 20 字符`（约 1259 字符，
超过 PATH_MAX）也是 500。

服务端日志里的两个真实抛出点（原始 traceback 尾部）：

```text
# companies/{dir}/*（数据层 glob）
File "scripts/webui/datastore/datasets.py", line 155, in _resolve_sources
    found.extend(sorted(base_path.glob(pattern)))
OSError: [Errno 63] File name too long: '…/output/aaaa…'

# collect/batches/{batch_id}
File "scripts/webui/plugins/collect.py", line 119, in _batch_detail
    return envelope.ok(json.loads(path.read_text(encoding="utf-8")))
OSError: [Errno 63] File name too long: '…/turtle_archive/batches/aaaa….json'
```

**为什么兜底没接住**（直接验证过机制，不是猜的）：`Path.resolve()` 对**不存在**的超长组件
**不抛异常**（realpath 容忍 lstat 失败，把拼接后的路径原样返回），所以
`except (OSError, ValueError)` 没触发、也不是 NUL 分支：

```text
a*255   bytes=255  resolve() OK   |  stat 2 No such file or directory
a*256   bytes=256  resolve() OK   |  stat 63 File name too long
汉*100  bytes=300  resolve() OK   |  stat 2 No such file or directory   （APFS 多字节按字符计）
safe_join(base, 'a'*256) -> 返回路径（未拒绝）
safe_join(base, '汉'*100) -> 返回路径（未拒绝）
```

ENAMETOOLONG 是在**下游**才出现的（数据层的 `glob` / `collect` 的 `read_text`），那里没有兜底。

- **影响（两类相同）**：不越权、不读树外内容、服务不崩，只是把「应该 4xx 的畸形输入」报成了
  500 INTERNAL（响应只有请求 id，堆栈只进日志）——与 `V6` 同类同级；`pages/*` 那一层仍能
  逐面板降级成 200 + warnings。
- **建议**：① 登记为 `V7`（若沿用你们的编号序列），并把 `V6` 登记里「符号链接环、超长路径
  同样归到 `PathOutsideRoot`」改成「NUL 已拦；环与超长见 `V7`」；② 修法：
  `safe_join` 的兜底加上 `RuntimeError`（覆盖 `pathlib.check_eloop`）与按**字节数/字符数**拒绝
  超长片段，并在数据层 `glob`、`collect` 的 `read_text` 外层把 `OSError` 归到
  `PathOutsideRoot`/`ArtifactMissing`；③ 建议与 `V2` 的路由层收敛一起排期。
- **它不改变本轮判定**：`AC-6` 要求的是「不越界、拒绝 `..`/绝对路径/越界符号链接」，这些都成立
  （环与超长都没有读出任何树外内容、也没有越过 jail）；`AC-3.6` 枚举的失败路径（坏 JSON、
  未知路由、越界路径、源文件缺失、表格格式变化）也不含「环/超长片段」。所以这是**非阻断的
  健壮性残留**，登记 + 排期即可。
